# Thesis 팀 제안 및 투자 암묵지 프로토타입 설명서

이 문서는 사용자의 투자 결정에서 드러나는 암묵지를 학습하는 `Thesis` 아이디어와 현재 프로토타입을 팀원에게 설명하고, SSAFY 8주 자율 프로젝트로 발전시킬 가치가 있는지 논의하기 위한 자료다.

결론부터 말하면 Thesis는 종목을 대신 추천하는 로보어드바이저가 아니다. 사용자가 기업을 찾고, 비교하고, 투자 가설을 만들고, 예외를 선택하고, 가설을 수정하는 전 과정을 기록하여 “나는 실제로 무엇을 중요하게 판단하는가”를 구체화하는 에이전트형 투자 리서치 브라우저다.

## 한 문장으로 설명하면

> 사용자의 말이 아니라 반복된 선택·제외·망설임·예외를 학습해 투자 판단 기준을 구체화하고, 다음 조사와 사후 검증에 다시 활용하는 개인 투자 의사결정 에이전트다.

## 해결하려는 문제

개인 투자자는 흔히 자신의 원칙을 다음처럼 설명한다.

- “성장성이 높은 회사를 좋아한다.”
- “비싸게 사는 것은 싫다.”
- “장기 투자한다.”
- “재무가 안정적인 기업을 선호한다.”

하지만 실제 선택에서는 원칙이 자주 충돌한다. 성장성이 높지만 비싼 기업을 매수하거나, 장기 투자한다고 말하면서 단기 가격 상승에 영향을 받거나, 손절 기준을 정해놓고도 지키지 못한다. 이때 사용자가 말한 취향과 실제 행동 사이에 존재하는 회색지대가 투자 판단의 암묵지다.

기존 투자 서비스는 주로 다음 중 하나에 집중한다.

- 시세와 차트 제공
- 뉴스·공시 요약
- 종목 추천 또는 점수화
- 포트폴리오 수익률 분석
- 투자 일지 작성

Thesis가 집중하는 대상은 수익률 자체가 아니라 `그 결정을 만든 과정`이다.

## 핵심 사용자

### 1차 사용자

- 투자 원칙은 있지만 실제 의사결정에서 일관되게 적용하지 못하는 개인 투자자
- 여러 기업과 자료를 비교하는 데 피로를 느끼는 투자자
- 자신이 왜 매수했는지 기록하고 이후에 검증하고 싶은 투자자
- AI의 일방적인 추천보다 근거와 반대 근거를 함께 확인하려는 투자자

### 사용자에게 제공하는 가치

1. 자연어 목표를 조사 가능한 조건으로 바꾼다.
2. 여러 기업의 공식 자료, 재무 지표, 뉴스와 위험 요인을 한 조사 흐름으로 묶는다.
3. 사용자가 실제로 선택한 비교 기준과 제외 이유를 기록한다.
4. 과거 행동과 다른 선택을 하면 충돌을 알려준다.
5. 예외를 선택한 이유를 낮은 신뢰도의 후보 규칙으로 저장한다.
6. 투자 후에는 당시 정한 무효화 조건이 실제 데이터에서 충족됐는지 감시한다.

## 제품의 핵심 구조

```text
자연어 투자 목표
        ↓
에이전트 조사 계획과 근거 수집
        ↓
후보 탐색·제외·비교 기준 선택
        ↓
투자 가설과 무효화 조건 작성
        ↓
Decision Gate에서 과거 행동과 충돌 확인
        ↓
모의 결정 기록
        ↓
Decision Twin 갱신
        ↓
실적·공시 기반 가설 사후 검증
```

Decision Twin은 별도의 부가 기능이 아니라 전체 서비스의 개인화 계층이다. 후보 순위, 기본 비교 지표, 충돌 감지, 예외 질문과 사후 알림이 모두 동일한 결정 기록을 사용한다.

## 현재 프로토타입의 사용자 흐름

프로토타입 주소는 `http://127.0.0.1:5174/#/thesis`다.

### 1. 투자 목표 입력

사용자가 다음처럼 자연어로 조사 목표를 입력한다.

> AI 반도체 성장성은 믿지만 이미 너무 오른 종목은 싫어. 한국과 미국에서 부채가 낮고 상대적으로 저평가된 후보를 찾아줘.

에이전트는 이를 성장성, 밸류에이션, 부채, 시장 범위라는 조사 조건으로 분해한다.

### 2. 에이전트 조사 과정 공개

결과만 생성하지 않고 다음 과정을 단계별로 보여준다.

- 의도와 조건 추출
- 기업 유니버스 탐색
- 재무 조건과 밸류에이션 검증
- 뉴스와 공시 수집 및 중복 제거
- 검토 후보와 반대 근거 구성

실제 서비스에서는 각 단계가 에이전트 작업 로그, 사용 도구, 출처와 연결된다.

### 3. 후보와 반대 근거 비교

현재 시연에서는 NVIDIA, SK하이닉스, 삼성전자를 비교한다. 사용자는 매출 성장률, P/E, Forward P/E, 부채비율, 잉여현금흐름, 변동성, AI 매출 노출도 중 원하는 지표를 직접 선택한다.

비교 지표를 선택하고 제거하는 행동도 사용자의 판단 기준을 보여주는 데이터가 된다.

### 4. 투자 가설 작성

사용자는 종목, 금액, 투자 기간, 확신도와 함께 다음을 기록한다.

- 핵심 근거
- 반대 근거
- 투자 가설
- 가설이 틀렸다고 인정할 수치형 조건

예를 들어 `AI 반도체 매출 성장률이 20% 아래로 하락`을 무효화 조건으로 저장할 수 있다.

### 5. Decision Gate

프로토타입의 과거 모의 결정 7건에서는 P/E 25배를 허용 상한으로 사용했다. 현재 선택한 NVIDIA의 P/E가 29.6배이므로 Decision Gate는 패턴 충돌을 감지한다.

사용자는 이번 선택이 달라진 이유를 명시한다.

- 기술 우위가 가격 부담보다 중요하다.
- 장기 성장률이 밸류에이션을 정당화한다.
- 최근 가격 상승에 영향을 받았다.
- 아직 판단하지 못했다.

이 질문은 사용자를 막기 위한 장치가 아니라 평소 기준을 깬 이유를 데이터로 바꾸는 장치다.

### 6. Decision Twin 갱신

현재 기본 프로필은 7개의 모의 결정으로 계산된다.

| 기준 | 기본 영향도 |
|---|---:|
| 성장성 | 68 |
| 저평가 | 72 |
| 기술 우위 | 58 |
| 재무 안정성 | 64 |
| 모멘텀 | 42 |

`기술 우위가 가격 부담보다 중요하다`를 선택하고 NVIDIA 모의 결정을 추가하면 8개 결정의 평균이 다음처럼 바뀐다.

| 기준 | 이전 | 이후 | 변화 |
|---|---:|---:|---:|
| 성장성 | 68 | 69 | +1 |
| 저평가 | 72 | 67 | -5 |
| 기술 우위 | 58 | 62 | +4 |
| 재무 안정성 | 64 | 63 | -1 |
| 모멘텀 | 42 | 42 | 0 |

한 번의 예외가 성향 전체를 뒤집지 않도록 신규 규칙은 `신뢰도 43%`, `근거 결정 1건`인 후보 상태로만 저장한다. 같은 행동이 반복될 때 신뢰도가 상승한다.

### 7. 투자 가설 사후 검증

새로운 실적이나 공시가 들어오면 저장된 무효화 조건과 비교한다. 단순히 주가가 떨어졌다는 이유가 아니라, 사용자가 결정 당시 정의한 가설의 핵심 조건이 깨졌을 때 재검토를 요청한다.

## Decision Twin이 학습하는 데이터

Decision Twin은 채팅에서 사용자가 자신을 설명한 문장만 학습하지 않는다.

### 결정 단위 데이터

- 선택한 기업과 제외한 기업
- 선택·제외 당시 확인한 지표
- 중요하게 본 비교 기준과 순서
- 투자 기간과 확신도
- 찬성 근거와 반대 근거
- 가설 무효화 조건
- 과거 기준을 완화한 예외와 그 이유
- 이후 가설을 수정하거나 유지한 행동

### 현재 프로토타입의 결정론적 계산

현재 버전은 AI가 성향 점수를 임의 생성하지 않는다.

1. 각 결정은 성장성, 저평가, 기술 우위, 재무 안정성, 모멘텀의 관찰값을 가진다.
2. 기준별 영향도는 누적 결정의 산술평균으로 계산한다.
3. 각 기준에서 영향이 컸던 결정 ID를 근거로 보존한다.
4. 반복된 행동 태그를 규칙 후보로 집계한다.
5. 단 한 번 나타난 예외는 확정 규칙이 아니라 낮은 신뢰도의 후보로 저장한다.
6. 모든 프로필 수치와 규칙은 원래 결정으로 역추적할 수 있다.

실제 제품에서는 단순 평균을 그대로 사용하기보다 시간 감쇠, 상황별 가중치, 사용자의 명시적 수정과 모델 불확실성을 함께 반영할 수 있다. 그러나 어떠한 모델을 사용하더라도 `왜 이 성향이 나왔는가`를 설명할 수 있어야 한다.

## 기존 LLM과의 차이

일반 LLM에도 “내 투자 성향에 맞는 종목을 골라줘”라고 요청할 수 있다. 그러나 대화 한 번으로는 다음을 안정적으로 수행하기 어렵다.

- 여러 세션에 걸친 결정 이력의 구조화
- 선택하지 않은 후보와 제외 이유 보존
- 당시 데이터 스냅샷과 판단의 연결
- 과거 기준과 현재 선택의 충돌 계산
- 투자 후 새로운 공시와 무효화 조건 비교
- 성향 점수와 규칙의 근거 결정 역추적

Thesis의 경쟁력은 LLM 답변 자체가 아니라 `결정 원장`, `근거 계보`, `행동 기반 프로필`, `사후 가설 감시`를 하나의 제품으로 묶는 데 있다.

## 기존 투자 서비스와의 차이

### 증권사 앱과 다른 점

증권사 앱은 시세 확인과 거래 실행에 강하지만 사용자가 왜 특정 후보를 제외했고 어떤 가설로 매수했는지 구조적으로 기록하지 않는다.

### 종목 추천 서비스와 다른 점

Thesis는 하나의 정답 종목이나 매수 점수를 제공하지 않는다. 사용자의 기준에 따라 조사 우선순위를 정하고 서로 충돌하는 근거를 노출한다.

### 투자 일지와 다른 점

일반적인 투자 일지는 결정 후 사용자가 직접 기록한다. Thesis는 조사와 비교 과정에서 행동 데이터를 자동으로 축적하고, 다음 결정과 사후 감시에 즉시 사용한다.

### 범용 에이전트 브라우저와 다른 점

범용 브라우저 에이전트는 자료를 찾아 작업을 수행하지만 투자 결정의 구조, 가설 무효화 조건, 예외 규칙과 행동 프로필을 도메인 모델로 갖지 않는다.

## 포트폴리오 측면의 기술적 강점

### 백엔드

- 기업·재무·공시·뉴스 데이터 수집 파이프라인
- 중복 기사 제거와 동일 이벤트 군집화
- 조사 세션, 후보, 근거, 반대 근거, 결정 스냅샷 저장
- 결정 시점의 데이터 버전과 이후 데이터 분리
- 무효화 조건을 실행 가능한 규칙으로 관리
- 이벤트 발생 시 영향을 받는 투자 가설 탐색
- 동일 입력과 동일 데이터에서 재현 가능한 에이전트 실행 로그
- 사용자별 Decision Twin 버전과 변경 이력 관리

### AI

- 자연어 투자 목표를 검색 조건과 비교 기준으로 구조화
- 공시·실적 발표·컨퍼런스콜에서 근거와 반대 근거 추출
- 서로 다른 기사를 동일 이벤트로 군집화
- 투자 가설을 모니터링 가능한 조건으로 변환
- 과거 결정과 현재 선택의 의미적 충돌 탐지
- 행동 기록에서 규칙 후보를 발견하되 신뢰도와 근거를 함께 제공
- 에이전트 작업 계획, 도구 실행, 검증과 실패 복구

AI가 가격, 재무 수치 또는 결정 이력을 임의로 생성하지 않도록 구조화된 데이터와 생성 결과를 분리해야 한다.

### 인프라

- 실시간 시세와 배치형 재무·공시 데이터의 갱신 주기 분리
- 수집 작업 스케줄링, 재시도와 실패 큐
- 원문 저장소, 검색 인덱스와 관계형 데이터베이스 분리
- 사용자별 에이전트 실행 비용과 토큰 사용량 추적
- 데이터 소스 장애 시 캐시와 마지막 정상 버전 사용
- 모델 응답 품질, 근거 누락률과 규칙 오탐 모니터링
- 개인정보와 투자 기록의 암호화 및 접근 제어

## DDD 기반 6인 협업 구조

6명이 기능 단위로 풀스택 개발한다면 다음 바운디드 컨텍스트로 나눌 수 있다.

| 컨텍스트 | 주요 책임 | 대표 결과물 |
|---|---|---|
| Research Orchestrator | 자연어 목표 분석, 조사 계획, 도구 실행 | 에이전트 실행 API·조사 화면 |
| Market Intelligence | 기업·재무·공시·뉴스 수집과 정규화 | 데이터 파이프라인·후보 탐색 |
| Evidence | 근거·반대 근거·출처·스냅샷 관리 | 근거 카드·데이터 계보 |
| Decision Workspace | 비교 기준, 투자 가설, 모의 결정 | 비교 보드·Decision Gate |
| Decision Twin | 행동 프로필, 규칙 후보, 충돌 탐지 | 성향 모델·설명 드로어 |
| Thesis Monitor | 무효화 조건 실행, 이벤트 감지, 알림 | 사후 검증·재검토 흐름 |

각 팀원은 자신의 컨텍스트에서 데이터 모델, 백엔드 API와 화면을 함께 책임진다. 공통 계약은 사용자 ID, 조사 세션 ID, 기업 식별자, 근거 ID, 결정 ID와 데이터 기준 시점으로 제한한다.

## 가장 어려운 부분

### 행동에서 판단 기준을 추론하는 문제

같은 기업을 매수했더라도 이유는 다를 수 있다. 가격이 싸서 선택했는지, 기술 우위를 중시했는지, 단순히 최근 상승에 영향을 받았는지 행동만으로 확정할 수 없다. 따라서 시스템은 자동 추론과 사용자의 짧은 확인 질문을 결합해야 한다.

### 한 번의 예외와 성향 변화를 구분하는 문제

한 번 비싼 기업을 샀다고 저평가 선호가 사라진 것은 아니다. 관찰 수, 반복 빈도, 상황 유사도와 시간에 따른 변화를 사용하고 후보 규칙과 확정 규칙을 구분해야 한다.

### 조사 시점의 사실을 보존하는 문제

재무 수치, 기사와 전망치는 계속 바뀐다. 나중에 과거 결정을 평가하려면 당시 사용한 데이터와 모델 결과를 그대로 재현할 수 있어야 한다.

### 자연어 무효화 조건을 실행하는 문제

“성장성이 훼손되면” 같은 문장은 그대로 감시할 수 없다. 어떤 지표가 어느 수준을 넘을 때, 어떤 출처로, 어느 주기로 평가할지 구조화해야 한다.

### 데이터 라이선스와 비용

실시간 시세와 뉴스는 기술적으로 수집 가능해도 재배포 권한과 비용이 문제가 될 수 있다. 초기에는 공시와 제한된 지연 데이터로 핵심 가치를 검증하는 편이 안전하다.

## 객관적인 약점과 실패 가능성

- 충분한 결정 기록이 쌓이기 전에는 개인화 품질이 낮다.
- 사용자가 이유 확인 질문에 답하지 않으면 행동의 의미가 모호해진다.
- 잘못 학습된 프로필이 다음 후보 순위를 편향시킬 수 있다.
- 투자 서비스처럼 보이지만 실제 추천 책임을 지지 않는 경계가 사용자에게 अस्पष्ट할 수 있다.
- 증권사 앱이나 범용 LLM이 비슷한 기록 기능을 추가하면 기능만으로는 쉽게 대체될 수 있다.
- 실제 투자 성과가 아니라 자기 이해를 제공하므로 일부 사용자는 효용을 약하게 느낄 수 있다.
- 공시와 재무 데이터를 안정적으로 연결하는 작업이 화면 구현보다 훨씬 어렵다.

따라서 제품은 “당신의 진짜 성향을 정확히 알아냈다”고 주장하면 안 된다. 관찰 횟수, 근거 결정, 불확실성과 사용자의 수정 기능을 항상 함께 제공해야 한다.

## 서비스가 주장하지 않는 것

- 특정 종목의 매수·매도를 추천하지 않는다.
- 높은 Decision Twin 적합도가 높은 수익률을 의미하지 않는다.
- 한 번의 선택으로 사용자의 투자 성향을 확정하지 않는다.
- AI가 생성한 근거나 수치를 공식 사실처럼 표시하지 않는다.
- 실제 거래를 사용자 승인 없이 실행하지 않는다.
- 모의 주문 결과를 실제 투자 성과로 표현하지 않는다.

## 현재 프로토타입의 상태

### 구현된 부분

- 자연어 투자 목표 입력
- 에이전트 조사 단계 시각화
- 국내 10개·미국 10개 시연용 기업 유니버스
- 후보 3개와 찬성·반대 근거
- 사용자 선택형 비교 지표
- 투자 가설과 무효화 조건 입력
- 과거 P/E 기준과 현재 선택의 충돌 감지
- 7개 모의 결정에서 계산한 기본 Decision Twin
- 새 결정 추가 후 영향도 재계산
- 신규 후보 규칙의 신뢰도·근거 수 표시
- 사후 가설 모니터링 시나리오

### 아직 구현하지 않은 부분

- 실제 백엔드와 사용자 계정
- 실제 거래 또는 증권사 연동
- 실시간 기업·재무·공시·뉴스 수집
- LLM 기반 에이전트 실행
- 자연어 조건 파서와 규칙 실행 엔진
- 데이터베이스 기반 결정 원장
- 지속적인 프로필 학습과 사용자 수정
- 실제 알림 인프라

현재 화면의 기업명과 일부 정적 수치는 제품 흐름을 보여주기 위한 데모 데이터다. Decision Twin의 변화는 고정 델타가 아니라 모의 결정 기록의 실제 평균 계산 결과지만, 해당 모의 기록 역시 실제 사용자의 투자 이력이 아니다.

## 팀 회의에서 사용할 3분 설명문

“제가 제안하는 첫 번째 아이디어는 Thesis라는 투자 리서치 에이전트입니다. 이 서비스의 핵심은 종목 추천이 아니라 투자 판단의 암묵지를 구체화하는 것입니다.

사람들은 보통 성장주를 좋아한다거나 비싸게 사는 것은 싫다고 말하지만, 실제로는 기준이 충돌하는 순간이 많습니다. Thesis는 사용자가 기업을 찾고, 후보를 제외하고, 비교 지표를 바꾸고, 투자 가설과 무효화 조건을 정하는 전 과정을 기록합니다.

예를 들어 과거 7번의 결정에서 P/E 25배 이상 기업을 계속 제외했던 사용자가 P/E 29.6배인 NVIDIA를 선택하면 Decision Gate가 과거 행동과 다르다고 알려줍니다. 그리고 이번에는 기술 우위가 가격 부담보다 중요했는지, 장기 성장률 때문인지, 최근 상승에 영향을 받은 것인지 묻습니다.

사용자가 기술 우위를 선택해도 한 번의 예외로 성향을 완전히 바꾸지는 않습니다. 현재 프로토타입에서는 성장성이 68에서 69, 저평가가 72에서 67, 기술 우위가 58에서 62로 바뀌고, 새로운 규칙은 신뢰도 43%인 후보로만 저장됩니다. 모든 수치와 규칙에는 어떤 결정이 근거가 됐는지 연결됩니다.

투자 후에는 사용자가 매수할 때 정한 무효화 조건을 신규 실적과 공시에서 감시합니다. 주가가 떨어졌다고 무조건 알리는 것이 아니라 당시 투자 가설이 실제 데이터로 깨졌을 때 재검토를 요청합니다.

기술적으로는 기업·공시·재무·뉴스 데이터 파이프라인, 에이전트 실행 상태 머신, 결정 시점 스냅샷, 행동 기반 프로필, 규칙 엔진과 사후 이벤트 처리가 필요합니다. 그래서 백엔드, AI, 데이터와 인프라 모두 포트폴리오로 보여줄 수 있습니다. 실제 주문은 하지 않고 제한된 기업 유니버스와 모의 결정으로 8주 안에 핵심 흐름을 완성하는 방향입니다.”

## 예상 질문과 답변

### 그냥 ChatGPT에게 내 성향을 기억하라고 하면 되지 않는가

대화 기억만으로는 선택하지 않은 후보, 비교 기준 변경, 당시 데이터 스냅샷, 예외의 반복 횟수와 사후 무효화 조건을 안정적으로 관리하기 어렵다. Thesis의 핵심은 LLM이 아니라 구조화된 결정 원장과 근거 계보다.

### 결국 투자 일지 아닌가

투자 일지는 사용자가 사후에 직접 작성한다. Thesis는 조사 과정에서 행동을 자동 수집하고 과거 행동과 충돌하는 순간 질문하며, 다음 조사와 사후 감시에 즉시 반영한다.

### 투자 추천 서비스와 무엇이 다른가

특정 종목의 정답 점수를 제공하지 않는다. 사용자가 중요하게 본 기준으로 검토 순서를 정하고, 찬성 근거와 반대 근거, 과거 행동과의 충돌을 함께 보여준다.

### 성향 점수는 어떤 근거로 계산하는가

현재 프로토타입은 7개 모의 결정의 기준별 관찰값을 평균하고 영향이 컸던 결정 ID를 근거로 남긴다. 실제 제품에서는 행동 이벤트, 반복 횟수, 시간 감쇠와 사용자 확인을 결합하되 모든 결과를 원래 결정으로 역추적할 수 있게 만든다.

### AI가 꼭 필요한가

단순 점수 평균에는 AI가 필요하지 않다. AI는 자연어 목표를 조사 계획으로 바꾸고, 방대한 공시와 뉴스에서 근거·반대 근거를 추출하며, 자연어 투자 가설을 감시 가능한 조건으로 구조화하고 규칙 후보를 제안하는 데 필요하다.

### 8주 안에 가능한가

실제 거래, 전 세계 기업과 모든 자연어 규칙을 지원하는 것은 불가능하다. 한국과 미국의 제한된 기업 유니버스, 공시 중심 데이터, 충돌 유형과 무효화 조건을 각각 2~3종으로 제한하면 핵심 수직 흐름은 구현할 수 있다.

### 투자 기록은 민감하지 않은가

민감한 금융 행동 데이터다. 사용자별 암호화, 접근 제어, 원문과 모델 학습 데이터 분리, 삭제와 내보내기 기능이 필요하다. 초기 프로젝트에서는 모의 투자만 지원하는 것이 적절하다.

## 팀에서 결정해야 할 사항

1. 종목 추천보다 `투자 판단 과정과 암묵지`를 핵심 가치로 삼는 데 공감하는가?
2. 실제 데이터 범위를 공시 중심으로 제한할 것인가, 유료 시세·뉴스 데이터까지 포함할 것인가?
3. Decision Twin의 첫 버전에서 어떤 행동을 반드시 학습할 것인가?
4. 사후 감시가 가능한 무효화 조건을 어떤 2~3종으로 제한할 것인가?
5. 8주 범위에서 실제 주문과 증권사 연동을 제외하는 데 동의하는가?

이 다섯 가지에 합의하면 다음 단계는 데이터 공급자 검증, 결정 이벤트 스키마 설계와 각 바운디드 컨텍스트의 API 계약 정의다.

## 프로토타입 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 다음 주소로 접속한다.

```text
http://127.0.0.1:5174/#/thesis
```

검증 명령은 다음과 같다.

```bash
npm test
npm run build
```

2. 자연어 조사 실행 버튼을 누른다.
3. 후보 기업과 반대 근거를 확인한다.
4. 비교 보드에서 지표를 변경한다.
5. NVIDIA 투자 가설을 만든다.

7. 예외 이유를 선택하고 모의 주문을 기록한다.
