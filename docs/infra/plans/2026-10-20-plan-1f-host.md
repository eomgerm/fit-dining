# 호스트 부트스트랩 구현 계획 (Plan 1F)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버를 받는 날 바로 쓸 수 있는 호스트 설정 스크립트를 만든다. 서버 A(`app`)와 B(`ops`)를 설계 3절의 상태(시간대, 스왑, 커널 값, Docker 설정과 정리, 방화벽, SSH 하드닝, fail2ban, 자동 보안 업데이트, 디렉터리와 계정, 공유 Docker 망)로 만드는 `bootstrap.sh`, 그 상태를 읽기만 해서 확인하는 `verify-host.sh`, 서버 없이 Ubuntu 컨테이너와 이 PC의 Docker로 시험하는 환경을 함께 만든다.

**Architecture:** `infra/host/` 한 디렉터리만 서버로 복사해 쓴다. 설정 파일은 `conf/`에 두고 `bootstrap.sh`가 내용·모드·소유자가 다를 때만 설치한다(멱등). 서버에서 사람이 한 번씩 돌리는 스크립트라 되돌릴 수 없는 실수(SSH 잠김, 허용 목록 밖 규칙 삭제, 동작 중인 컨테이너 재시작)를 막는 안전장치를 스크립트에 넣는다. 시험은 Ubuntu 22.04·24.04 컨테이너에서 실제로 적용하고 점검하며, 설정을 하나씩 망가뜨려 `verify-host.sh`가 잡는지 본다.

**Tech Stack:** bash, Ubuntu 22.04·24.04(apt, ufw, openssh-server, fail2ban, unattended-upgrades, systemd 유닛), Docker Engine(공식 apt 저장소), Docker Compose v2.

**Spec:** [docs/infra/design.md](../design.md) (2.2절 네트워크, 3절 호스트 기반, 13.3절 SSH 매트릭스)

## 한눈에 보기

각 Task는 구현, 통과 확인, 커밋 순서다(커밋은 허용된 경우에만). Task 2는 시험을 먼저 쓴다.

| Task | 만드는 것 | 막는 사고 |
|---|---|---|

| 2 | `docker-prune.sh`, `networks.sh`와 그 시험 | 이미지가 쌓여 디스크가 참, 롤백에 쓸 직전 이미지까지 지워짐, 공유 망의 `internal` 설정 누락 |
| 3 | `bootstrap.sh`, `verify-host.sh` | 수작업 설정이 서버마다 다름, SSH 키 없이 비밀번호 로그인을 꺼서 잠김, 허용 목록 밖 포트가 조용히 열려 있음 |

이 계획은 호스트 설정만 만든다. 재부팅 뒤 기동 순서(`fit-up.sh`)는 compose 프로젝트(`data`, `app`)가 생기는 계획 1C-2가 만든다. 금고 계정의 `rrsync` 키 등록과 백업 타이머는 계획 1D가, 러너 등록은 서버가 생긴 뒤의 계획 2가 맡는다.

## 검증 결과

이 계획의 코드는 저장소를 clone한 임시 복사본(저장소 밖)에서 계획의 코드 블록만으로 다시 만들어 실행해 확인했다.

- 컨테이너 시험(`test-host.sh all`)은 Ubuntu 24.04와 22.04의 app, ops 네 조합이 모두 통과한다(조합마다 `PASS` 35개, `FAIL` 0개). 컨테이너마다 패키지와 Docker Engine(공식 apt 저장소)을 실제로 설치한다.
- 멱등: 같은 `bootstrap.sh`를 두 번째 실행하면 `변경 없음`으로 끝난다.
- 시험이 죽은 검사가 아닌지 확인하려고 설정을 일부러 망가뜨렸다(허용 목록 밖 ufw 규칙, 비밀번호 로그인 켜기, 시간대, fail2ban 감옥 삭제, `daemon.json` 변경, `/etc/fit` 권한, 자동 재부팅 켜기, `fit-dev` 터널 제한 해제 또는 `vault` 전달 허용, 허용 목록 밖 포트 2222 열기). 모든 경우에 `verify-host.sh`가 실패하고 bootstrap(ufw 규칙과 열린 포트는 사람이 지운다)으로 고친 뒤 통과한다.
- 잠금 방지: 키가 등록된 로그인 계정이 없는 서버에서는 bootstrap이 거부하고 SSH 설정 파일을 만들지 않는다. 깨진 SSH 설정(`sshd -t` 실패)은 이전 파일로 되돌린다. `FIT_PEER_IP`에 IP가 아닌 값(명령 주입)을 주면 거부한다.
- SSH 설정 순서: 클라우드 이미지의 `60-cloudimg-settings.conf`(`PasswordAuthentication yes`)가 있어도 `10-fit.conf`가 먼저 적용된다. `Match User` 블록은 `fit-dev`(또는 `vault`)에만 적용되고 일반 계정의 포트 전달은 막히지 않는다(`sshd -T -C`).
- 점검 출력은 IP와 공개키 값을 포함하지 않는다.
- Docker 정리(`docker-prune.sh`)는 be의 SHA 태그 중 최근 5개를 남기고 오래된 것을 지운다. 컨테이너가 쓰는 오래된 이미지는 지우지 않고 알리며, `latest`와 SHA 모양이 아닌 태그는 건드리지 않는다. 역할을 모르면 종료 코드 2다. 공유 망(`networks.sh`)은 여섯 개를 만들고, 다시 실행해도 새로 만들지 않으며, `net-data`만 `internal`이다. `internal`이 다르거나 망이 빠지면 실패로 잡는다.
- 22.04 컨테이너에서만 난 오류가 있었다. `sshd -T | awk '… exit'`에서 awk가 먼저 끝나면 sshd가 SIGPIPE로 죽고, `pipefail` 때문에 bootstrap이 오류 메시지 없이 멈췄다(24.04에서는 타이밍 때문에 나지 않았다). 입력을 끝까지 읽도록 고쳤고 두 버전 모두 통과한다.
- 전체 러너와 러너 자가 테스트 10종이 통과한다. 새 스크립트는 `lint:shell`(`find infra -name '*.sh'`)이 자동으로 검사한다.
- 컨테이너로 확인할 수 없는 것: 이 PC의 Docker는 arm64 컨테이너를 실행하지 못해(`exec format error`) B의 CPU 구조 점검은 건너뛰었다. 컨테이너에는 systemd와 Docker 데몬이 없고 커널 설정은 호스트와 공유되어 스왑, sysctl 적용, 시간 동기화, 데몬 상태, 정리 타이머와 fail2ban의 실제 동작은 건너뛰었다. WSL의 Ubuntu는 `sudo`에 비밀번호가 필요하고 시스템을 바꾸므로 시험에 쓰지 않았다.
- 시험 중 두 번(리허설), 첫 bootstrap 실행 직후의 점검 하나가 실패했다. 같은 시험을 아홉 번 더 돌렸을 때는 재현되지 않아 패키지 내려받기의 일시 실패로 추정한다. 그래서 `apt-get`과 `curl`에 재시도를 넣었고, 잠금 방지 시험은 패키지를 설치한 뒤에 하며, 시험은 첫 적용이 실패하면 한 번 더 실행한다. 실패한 점검의 직전 출력을 보여 주도록 진단도 넣었다.

아래 코드를 그대로 옮기면 같은 결과가 나와야 한다. 다르면 코드를 고치기 전에 원인을 먼저 확인한다.

**아직 확인하지 못한 것**

- 실제 서버에서의 실행. 스왑 생성과 `vm.max_map_count` 적용, 시간 동기화, Docker 데몬(`live-restore`)과 정리 타이머·fail2ban의 실제 동작, ufw의 실제 차단, 공유 Docker 망 생성은 컨테이너에서 확인할 수 없어 `FIT_SKIP`으로 건너뛰었다. 서버에서 `verify-host.sh`가 점검한다.
- 실제 SSH 접속. `fit-dev`의 터널 제한은 `sshd -T -C`로 설정 값만 확인했다. 키 로그인과 터널이 실제로 되는지는 서버에서 본다.
- 서버의 초기 상태. SSAFY가 미리 넣어 둔 ufw 규칙(선배 팀은 22·8000·8001이 열려 있었다)이 있으면 bootstrap은 지우지 않고 알리기만 하고 `verify-host.sh`가 실패로 보고한다. 사람이 `ufw delete`로 정리한다.
- Ubuntu 22.04와 24.04만 시험했다. 서버가 다른 버전이면 경고만 내고 진행하며 Ubuntu가 아니면 멈춘다.
- B(Arm)의 CPU 구조 점검. 시험 컨테이너가 x86이라 `arch` 점검을 건너뛰었다.
- 클라우드 방화벽(Lightsail 네트워킹 탭, EC2 보안 그룹)과 고정 IP. 사람이 확인한다.

## Global Constraints

1A·1B·1C-1의 전역 제약이 모두 적용된다([plan 1A](2026-10-15-plan-1a-foundation-guardrails.md), [plan 1B](2026-10-19-plan-1b-local-env-contracts.md), [plan 1C-1](2026-10-20-plan-1c1-edge.md)). 이 계획에서 더 지키는 것은 다음과 같다.

### Task 1: 설정 파일

**목표:** 서버에 설치될 설정을 파일로 정한다. 값은 설계 3절과 13.3절을 그대로 옮긴다.

**Files:**
- Create: `infra/host/conf/sshd-common.conf`, `sshd-app.conf`, `sshd-ops.conf`
- Create: `infra/host/conf/sysctl-common.conf`, `sysctl-app.conf`
- Create: `infra/host/conf/daemon-app.json`, `daemon-ops.json`
- Create: `infra/host/conf/fail2ban-fit.local`, `apt-fit.conf`
- Create: `infra/host/conf/systemd/fit-docker-prune.service`, `fit-docker-prune.timer`

**Interfaces:**
- Produces: `bootstrap.sh`가 설치하고 `verify-host.sh`가 같은 파일과 비교한다. SSH 설정은 `sshd-common.conf`에 역할 파일(`sshd-app.conf` 또는 `sshd-ops.conf`)을 이어 붙여 `/etc/ssh/sshd_config.d/10-fit.conf`가 된다.

핵심 결정:

- SSH 파일 이름은 `10-fit.conf`다. sshd는 같은 키워드의 첫 값을 쓰고 `sshd_config.d`를 이름 순서로 읽으므로 클라우드 이미지의 `60-cloudimg-settings.conf`(`PasswordAuthentication yes`일 수 있다)보다 먼저 읽혀야 한다.
- `Match User` 블록은 같은 파일의 맨 끝에 둔다. 그 사용자에게만 적용되고 다른 계정의 설정은 바뀌지 않는다(Task 4에서 확인한다).
- A의 `fit-dev`는 셸 없이 개발 포트 세 개(3000, 8888, 5432)로 터널만 만든다. B의 `vault`는 포트 전달·TTY·사용자 rc를 막고 허용 명령은 `authorized_keys`의 `command=`(계획 1D)가 정한다.
- `live-restore`는 A에만 켠다. 로그는 `json-file` 10MB×3이다(be·fe·caddy는 compose에서 50MB×5로 덮어쓴다).
- 정리 타이머는 일요일 03:00(서버 시간대 Asia/Seoul)이다. 새벽 4시 BE 배치와 겹치지 않게 한다.

- [ ] **Step 2: SSH 설정 파일 작성**

`infra/host/conf/sshd-common.conf`:

````text
# 모든 서버 공통 SSH 하드닝(설계 3절). /etc/ssh/sshd_config.d/10-fit.conf로 설치된다.
# sshd는 같은 키워드의 첫 값을 쓰고 sshd_config.d/*.conf를 파일 이름 순서로 읽는다.
# 클라우드 이미지의 60-cloudimg-settings.conf보다 먼저 읽히도록 10번을 쓴다.
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
X11Forwarding no
AllowAgentForwarding no
MaxAuthTries 3
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2
````

`infra/host/conf/sshd-app.conf`:

````text

# 팀원 터널 계정(설계 13.3절): 셸 없이 개발용 포트 세 개로 터널만 만든다.
Match User fit-dev
    AllowTcpForwarding local
    PermitOpen 127.0.0.1:3000 127.0.0.1:8888 127.0.0.1:5432
    PermitTTY no
    ForceCommand /usr/sbin/nologin
````

`infra/host/conf/sshd-ops.conf`:

````text

# 금고 전송 계정(설계 13.3절): A가 쓰기 전용으로 덤프를 올린다. 허용 명령은 authorized_keys의 command=(rrsync)가 정한다.
Match User vault
    AllowTcpForwarding no
    PermitTTY no
    PermitUserRC no
````

- [ ] **Step 1: 시험 스크립트 작성 (스크립트보다 먼저)**

컨테이너 시험(`all`, 인자 없음)은 Task 4에서 `run-in-container.sh`를 만든 뒤 쓴다. 이 Task에서는 `prune`만 쓴다.

````bash
#!/usr/bin/env bash
# 호스트 설정 스크립트를 노트북에서 시험한다(설계 10.5절). 서버가 없어도 Ubuntu 컨테이너와 이 PC의 Docker로 확인한다.
#   bash infra/host/test/test-host.sh            # Ubuntu 24.04에서 app과 ops
#   bash infra/host/test/test-host.sh all        # 24.04와 22.04에서 app과 ops
#   bash infra/host/test/test-host.sh prune      # docker-prune.sh와 networks.sh를 이 PC의 Docker로 시험
# 컨테이너는 --rm으로 지워진다. 필요한 것: docker, git. 컨테이너 시험은 Docker Engine 설치까지 하므로 조합당 몇 분 걸린다.
set -euo pipefail

ROOT="$(git rev-parse --show-toplevel)"
cd "$ROOT"
case "$(uname -s)" in
  MINGW* | MSYS*) export MSYS_NO_PATHCONV=1 ;;
esac
W="$(pwd -W 2>/dev/null || pwd)"

in_container() { # in_container 우분투버전 역할
  echo "=== Ubuntu $1, ROLE=$2"
  docker run --rm -e FIT_TEST_VERBOSE="${FIT_TEST_VERBOSE:-}" --cap-add NET_ADMIN --cap-add NET_RAW -v "$W/infra/host:/opt/fit-host:ro" "ubuntu:$1" bash /opt/fit-host/test/run-in-container.sh "$2"
}

FAILED=0
pass() { printf 'PASS  %s\n' "$1"; }
fail() { printf 'FAIL  %s\n' "$1"; FAILED=$((FAILED + 1)); }
ok_if() { if [ "$2" = "1" ]; then pass "$1"; else fail "$1"; fi; }
has() { case "$1" in *"$2"*) echo 1 ;; *) echo 0 ;; esac; }

PREFIX=fit-hosttest-
TEST_REPO=fit-hosttest
cleanup_prune() {
  docker rm -f fit-hosttest-keep >/dev/null 2>&1 || true
  for r in "$TEST_REPO/be" "$TEST_REPO/fe"; do
    docker image ls "$r" -q 2>/dev/null | sort -u | xargs -r docker image rm -f >/dev/null 2>&1 || true
  done
  for n in net-edge net-prod net-dev net-data net-obs net-dbaccess; do docker network rm "$PREFIX$n" >/dev/null 2>&1 || true; done
}

prune_and_networks() {
  trap cleanup_prune EXIT
  cleanup_prune
  echo "=== docker-prune.sh"
  # be는 서로 다른 이미지 7개(SHA 태그), fe는 3개를 만든다. 오래된 순서로 만들어야 "최근 5개"가 정해진다
  local i tag
  for i in 1 2 3 4 5 6 7; do
    tag="$(printf '%07x' $((0xabc000 + i)))"
    printf 'FROM ubuntu:24.04\nRUN echo be-%s > /n\n' "$i" | docker build -q -t "$TEST_REPO/be:$tag" - >/dev/null
    sleep 1
  done
  for i in 1 2 3; do
    tag="$(printf '%07x' $((0xdef000 + i)))"
    printf 'FROM ubuntu:24.04\nRUN echo fe-%s > /n\n' "$i" | docker build -q -t "$TEST_REPO/fe:$tag" - >/dev/null
    sleep 1
  done
  docker tag "$TEST_REPO/be:$(printf '%07x' $((0xabc000 + 7)))" "$TEST_REPO/be:latest"
  docker tag "$TEST_REPO/be:$(printf '%07x' $((0xabc000 + 1)))" "$TEST_REPO/be:rc1"
  # 가장 오래된 SHA 이미지(abc001)는 rc1 태그도 달려 있다. 가장 오래된 둘 중 하나(abc002)를 컨테이너가 쓴다
  docker run -d --name fit-hosttest-keep "$TEST_REPO/be:$(printf '%07x' $((0xabc000 + 2)))" sleep 600 >/dev/null
  local out
  out="$(FIT_ROLE=app FIT_PRUNE_REPOS="$TEST_REPO/be $TEST_REPO/fe" FIT_PRUNE_KEEP=5 bash infra/host/docker-prune.sh 2>&1)"
  echo "$out"
  local be_tags fe_tags
  be_tags="$(docker image ls "$TEST_REPO/be" --format '{{.Tag}}' | sort | tr '\n' ' ')"
  fe_tags="$(docker image ls "$TEST_REPO/fe" --format '{{.Tag}}' | sort | tr '\n' ' ')"
  ok_if "prune: be는 최근 SHA 5개를 남긴다(abc003~abc007)" "$([ "$(has "$be_tags" abc003)$(has "$be_tags" abc004)$(has "$be_tags" abc005)$(has "$be_tags" abc006)$(has "$be_tags" abc007)" = 11111 ] && echo 1 || echo 0)"
  ok_if "prune: 컨테이너가 쓰는 오래된 이미지(abc002)는 지우지 않고 알린다" "$([ "$(has "$be_tags" abc002)$(has "$out" '남김: '"$TEST_REPO"'/be:0abc002')" = 11 ] && echo 1 || echo 0)"
  ok_if "prune: 쓰지 않는 오래된 SHA 이미지(abc001)는 지운다. 같은 이미지의 rc1 태그는 SHA 모양이 아니라 남는다" "$([ "$(has "$be_tags" abc001)$(has "$be_tags" rc1)" = 01 ] && echo 1 || echo 0)"
  ok_if "prune: latest 같은 태그는 건드리지 않는다" "$(has "$be_tags" latest)"
  ok_if "prune: SHA 태그가 5개 이하인 fe는 그대로다" "$([ "$(has "$fe_tags" def001)$(has "$fe_tags" def002)$(has "$fe_tags" def003)" = 111 ] && echo 1 || echo 0)"
  local rc
  FIT_ROLE='' bash infra/host/docker-prune.sh >/dev/null 2>&1 && rc=0 || rc=$?
  ok_if "prune: 역할을 모르면 종료 코드 2로 멈춘다" "$([ "$rc" = 2 ] && echo 1 || echo 0)"

  echo "=== networks.sh"
  out="$(FIT_NET_PREFIX=$PREFIX bash infra/host/networks.sh)"
  ok_if "networks: 여섯 개를 만든다" "$([ "$(printf '%s\n' "$out" | grep -c '^만듦')" = 6 ] && echo 1 || echo 0)"
  out="$(FIT_NET_PREFIX=$PREFIX bash infra/host/networks.sh)"
  ok_if "networks: 다시 실행하면 새로 만들지 않고 OK만 낸다" "$([ "$(printf '%s\n' "$out" | grep -c '^OK')" = 6 ] && echo 1 || echo 0)"
  ok_if "networks: net-data만 internal이다" \
    "$([ "$(docker network inspect -f '{{.Internal}}' ${PREFIX}net-data)$(docker network inspect -f '{{.Internal}}' ${PREFIX}net-edge)" = truefalse ] && echo 1 || echo 0)"
  FIT_NET_PREFIX=$PREFIX bash infra/host/networks.sh check >/dev/null 2>&1 && rc=0 || rc=$?
  ok_if "networks: check는 모두 있으면 통과한다" "$([ "$rc" = 0 ] && echo 1 || echo 0)"
  docker network rm "${PREFIX}net-data" >/dev/null
  docker network create "${PREFIX}net-data" >/dev/null
  out="$(FIT_NET_PREFIX=$PREFIX bash infra/host/networks.sh check 2>&1)" && rc=0 || rc=$?
  ok_if "networks: internal이 아닌 net-data는 실패로 잡는다" "$([ "$rc" = 1 ] && [ "$(has "$out" 'FAIL  '"${PREFIX}"'net-data: internal=false')" = 1 ] && echo 1 || echo 0)"
  docker network rm "${PREFIX}net-obs" >/dev/null
  out="$(FIT_NET_PREFIX=$PREFIX bash infra/host/networks.sh check 2>&1)" && rc=0 || rc=$?
  ok_if "networks: check는 빠진 망을 만들지 않고 실패로 잡는다" "$([ "$rc" = 1 ] && [ "$(has "$out" '없다')" = 1 ] && ! docker network inspect "${PREFIX}net-obs" >/dev/null 2>&1 && echo 1 || echo 0)"
  if [ "$FAILED" -gt 0 ]; then
    printf '\n%d개 시험 실패\n' "$FAILED"
    return 1
  fi
  printf '\nprune·networks 시험 통과\n'
}

case "${1:-default}" in
  default)
    in_container 24.04 app
    in_container 24.04 ops
    ;;
  all)
    for v in 24.04 22.04; do
      in_container "$v" app
      in_container "$v" ops
    done
    ;;
  prune) prune_and_networks ;;
  *)
    echo "사용: bash infra/host/test/test-host.sh [all|prune]" >&2
    exit 2
    ;;
esac
````

`infra/host/docker-prune.sh`:

````bash
#!/usr/bin/env bash
# Docker 이미지와 빌더 캐시를 정리한다(설계 3절). systemd 타이머(fit-docker-prune.timer)가 주 1회 부른다.
#   app(서버 A): be·fe 이미지는 SHA 태그 중 최근 5개만 남긴다. 롤백이 직전 색의 이미지를 쓰므로 그 밖의 이미지는 지우지 않는다.
#   ops(서버 B): 7일 넘게 쓰지 않은 이미지를 모두 지운다. 러너가 필요하면 다시 받는다.
# 볼륨은 지우지 않는다(데이터가 있다).
# 환경변수: FIT_ROLE(기본은 /etc/fit/role), FIT_PRUNE_KEEP(기본 5), FIT_PRUNE_REPOS(app의 대상 이미지 이름, 기본 "be fe")
set -euo pipefail

ROLE="${FIT_ROLE:-$(cat /etc/fit/role 2>/dev/null || true)}"
KEEP="${FIT_PRUNE_KEEP:-5}"
REPOS="${FIT_PRUNE_REPOS:-be fe}"

case "$ROLE" in
  app)
    for repo in $REPOS; do
      # docker image ls는 만든 시각이 최근인 순서로 보여 준다. SHA 모양의 태그만 센다(latest 같은 태그는 건드리지 않는다)
      { docker image ls "$repo" --format '{{.Tag}}' | grep -E '^[0-9a-f]{7,40}$' || true; } |
        tail -n +"$((KEEP + 1))" |
        while read -r tag; do
          # 컨테이너가 쓰는 이미지는 docker가 지우기를 거부한다. 그대로 두고 넘어간다
          docker image rm "$repo:$tag" >/dev/null 2>&1 || echo "남김: $repo:$tag (사용 중)"
        done
    done
    docker image prune -f >/dev/null
    docker builder prune -f --filter "until=168h" >/dev/null
    ;;
  ops)
    docker image prune -af --filter "until=168h" >/dev/null
    docker builder prune -af --filter "until=168h" >/dev/null
    ;;
  *)
    echo "역할을 알 수 없다(/etc/fit/role 또는 FIT_ROLE: app|ops)" >&2
    exit 2
    ;;
esac
echo "prune 완료($ROLE)"
````

`infra/host/networks.sh`:

````bash
#!/usr/bin/env bash
# 서버 A의 공유 Docker 망을 만든다(설계 2.2절). 몇 번 실행해도 같은 결과다. compose 프로젝트들이 이 망을 `external`로 붙인다.
#   bash infra/host/networks.sh          # 없는 망을 만들고 있는 망은 확인한다
#   bash infra/host/networks.sh check    # 만들지 않고 확인만 한다(있는지, net-data가 internal인지)
# FIT_NET_PREFIX로 이름 앞에 접두사를 붙일 수 있다(시험용). 하나라도 어긋나면 종료 코드 1이다.
set -euo pipefail

PREFIX="${FIT_NET_PREFIX:-}"
# net-data는 바깥으로 나가지 못하는 internal 망이다. 나머지는 일반 bridge다
NETS="net-edge net-prod net-dev net-data net-obs net-dbaccess"
INTERNAL="net-data"
MODE="${1:-create}"

bad=0
for n in $NETS; do
  name="$PREFIX$n"
  want=false
  case " $INTERNAL " in *" $n "*) want=true ;; esac
  if docker network inspect "$name" >/dev/null 2>&1; then
    got="$(docker network inspect -f '{{.Internal}}' "$name")"
    if [ "$got" = "$want" ]; then
      echo "OK    $name"
    else
      echo "FAIL  $name: internal=$got, 기대값은 $want. 망을 지우고 다시 만들어야 한다"
      bad=1
    fi
  elif [ "$MODE" = "check" ]; then
    echo "FAIL  $name: 없다"
    bad=1
  else
    args=(network create --driver bridge --label com.fit.managed=true)
    if [ "$want" = true ]; then args+=(--internal); fi
    docker "${args[@]}" "$name" >/dev/null
    echo "만듦  $name"
  fi
done
exit "$bad"
````

**목표:** 서버를 설계 3절의 상태로 만드는 `bootstrap.sh`와 그 상태를 읽기만 해서 확인하는 `verify-host.sh`를 만든다.

**Interfaces:**
- `sudo ROLE=app|ops [FIT_PEER_IP=…] [FIT_FORCE_SSH=1] [FIT_SKIP=…] bash bootstrap.sh`: 멱등. 마지막 줄 전에 `변경 없음` 또는 `변경 N건`을 낸다. 실패하면 `FAIL …`을 stderr로 내고 종료 코드 1이다.
- `sudo [ROLE=…] bash verify-host.sh`: 점검마다 `PASS`·`FAIL`·`SKIP`만 출력하고 하나라도 FAIL이면 종료 코드 1이다. root가 아니면 종료 코드 2다. 역할은 `/etc/fit/role`에서 읽는다.
- Consumes: Task 1의 `conf/`, Task 2의 `docker-prune.sh`와 `networks.sh`
- 만드는 상태: 시간대 Asia/Seoul, 스왑(A 4GB, B 2GB), sysctl(`vm.swappiness=10`, A는 `vm.max_map_count=262144`), Docker와 `daemon.json`, 정리 타이머, `/etc/fit/{role,keys}`, A의 `/srv/fit/{state,web,backups}`와 `fit-dev`, B의 `/srv/vault/{incoming,store}`와 `vault`, fail2ban, 자동 보안 업데이트(재부팅 없음), SSH 하드닝, ufw(A는 22 limit·80·443, B는 22 limit), A의 공유 Docker 망.

핵심 결정:

- **순서:** 패키지, 시간대, 스왑, sysctl, Docker, 정리 타이머, 계정과 디렉터리, fail2ban, 자동 업데이트, SSH, ufw, 망. 접속을 끊을 수 있는 SSH와 ufw를 뒤에 둔다.
- **잠금 방지:** 키가 한 줄이라도 등록된 일반 로그인 계정(`fit-dev`, `vault` 제외)이 없으면 SSH 하드닝을 하지 않고 멈춘다. `sshd -t`가 실패하면 이전 파일로 되돌린다. sshd가 22번 포트가 아니면 ufw를 건드리지 않는다. 22 허용 규칙을 넣은 뒤에 ufw를 켠다.
- **파괴하지 않는다:** 허용 목록 밖의 ufw 규칙은 지우지 않고 알린다. Docker가 이미 있으면 설치하지 않는다. 기존 `daemon.json`은 한 번 백업하고, 컨테이너가 돌고 있으면 Docker를 재시작하지 않는다.
- **네트워크:** 패키지와 Docker 저장소를 내려받는 `apt-get`은 `Acquire::Retries=3`, `curl`은 `--retry 3`으로 일시적인 실패를 다시 시도한다.
- **`FIT_SKIP`:** 시험 환경(컨테이너)에서 못 하는 단계만 건너뛴다(`docker-install`, `swap`, `sysctl-apply`, `systemd`, `networks`, `arch`). 서버에서는 쓰지 않는다.
- **verify의 범위:** 설정 파일은 저장소의 `conf/`와 같은지 비교하고, 동작은 실제 값(`sshd -T`, `ufw show added`, `ss -lnt`, `apt-config dump`, `docker info`)으로 본다. 열린 TCP 포트는 루프백이 아닌 리스너가 허용 목록(A는 22·80·443, B는 22) 안인지 본다(Docker가 게시한 포트도 잡힌다).

````bash
#!/usr/bin/env bash
# 서버가 설계 3절의 상태인지 점검한다. 읽기만 하고 아무것도 바꾸지 않는다. 점검마다 PASS, FAIL, SKIP만 출력하고 값(IP, 키)은 찍지 않는다.
#   sudo bash infra/host/verify-host.sh             # 역할은 /etc/fit/role에서 읽는다
#   sudo ROLE=app bash infra/host/verify-host.sh    # 역할을 지정한다
# 환경변수: FIT_PEER_IP(있으면 fail2ban ignoreip에 들어 있는지 본다), FIT_SKIP(bootstrap.sh와 같다), FIT_NET_PREFIX(networks.sh와 같다)
# 하나라도 FAIL이면 종료 코드 1이다.
set -u

HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
CONF="$HERE/conf"
SKIP=",${FIT_SKIP:-},"
FAILED=0

pass() { printf 'PASS  %s\n' "$1"; }
fail() { printf 'FAIL  %s\n' "$1"; FAILED=$((FAILED + 1)); }
skip() { printf 'SKIP  %s\n' "$1"; }
ok_if() { if [ "$2" = 1 ]; then pass "$1"; else fail "$1"; fi; } # ok_if 이름 1|0
is() { if [ "$1" = "$2" ]; then echo 1; else echo 0; fi; }
succeeds() { if "$@" >/dev/null 2>&1; then echo 1; else echo 0; fi; } # succeeds 명령...: 성공하면 1
skipped() { case "$SKIP" in *",$1,"*) return 0 ;; esac; return 1; }
file_is() { # file_is 경로 모드 소유자:그룹
  if [ -e "$1" ] && [ "$(stat -c %a "$1")" = "$2" ] && [ "$(stat -c %U:%G "$1")" = "$3" ]; then echo 1; else echo 0; fi
}

if [ "$(id -u)" != 0 ]; then
  echo "root로 실행한다(sudo). ufw와 sshd 설정을 읽으려면 필요하다" >&2
  exit 2
fi
ROLE="${ROLE:-$(cat /etc/fit/role 2>/dev/null || true)}"
case "$ROLE" in
  app | ops) ;;
  *)
    echo "역할을 알 수 없다. ROLE=app|ops를 주거나 bootstrap.sh를 먼저 실행한다" >&2
    exit 2
    ;;
esac
echo "ROLE=$ROLE"

sshd_value() { # sshd_value 사용자 키워드: 그 사용자에게 적용되는 값(소문자 키워드)
  sshd -T -C "user=$1,host=verify,addr=192.0.2.1" 2>/dev/null | awk -v k="$2" '$1 == k { $1 = ""; sub(/^ /, ""); print; exit }'
}

check_system() {
  echo "-- 시스템"
  # shellcheck disable=SC1091
  . /etc/os-release
  case "${ID:-}:${VERSION_ID:-}" in
    ubuntu:22.04 | ubuntu:24.04) pass "OS는 시험한 Ubuntu LTS다" ;;
    *) fail "OS가 Ubuntu 22.04 또는 24.04가 아니다" ;;
  esac
  local want=x86_64
  if [ "$ROLE" = ops ]; then want=aarch64; fi
  if skipped arch; then skip "CPU 구조 (FIT_SKIP=arch)"; else ok_if "CPU 구조가 ROLE=$ROLE에 맞다($want)" "$(is "$(uname -m)" "$want")"; fi
  local cur
  cur="$(readlink -f /etc/localtime 2>/dev/null || true)"
  ok_if "시간대는 Asia/Seoul이다" "$(is "${cur##*/zoneinfo/}$(cat /etc/timezone 2>/dev/null || true)" "Asia/SeoulAsia/Seoul")"
  if skipped systemd; then skip "시간 동기화 (FIT_SKIP=systemd)"; else
    ok_if "시간이 동기화돼 있다" "$(is "$(timedatectl show -p NTPSynchronized --value 2>/dev/null)" yes)"
  fi
  if grep -qx 'vm.swappiness = 10' /etc/sysctl.d/90-fit-common.conf 2>/dev/null; then pass "sysctl 설정 파일: swappiness 10"; else fail "sysctl 설정 파일: swappiness 10"; fi
  if [ "$ROLE" = app ]; then
    if grep -qx 'vm.max_map_count = 262144' /etc/sysctl.d/91-fit-app.conf 2>/dev/null; then pass "sysctl 설정 파일: max_map_count 262144"; else fail "sysctl 설정 파일: max_map_count 262144"; fi
  fi
  if skipped sysctl-apply; then skip "커널 값 적용 (FIT_SKIP=sysctl-apply)"; else
    ok_if "swappiness가 10이다" "$(is "$(sysctl -n vm.swappiness)" 10)"
    if [ "$ROLE" = app ]; then ok_if "max_map_count가 262144다" "$(is "$(sysctl -n vm.max_map_count)" 262144)"; fi
  fi
  if skipped swap; then skip "스왑 (FIT_SKIP=swap)"; else
    local want_mb=2048 cur_mb
    if [ "$ROLE" = app ]; then want_mb=4096; fi
    cur_mb="$(awk '/^SwapTotal:/ { print int($2 / 1024) }' /proc/meminfo)"
    ok_if "스왑이 목표(${want_mb}MB)의 95% 이상이다" "$([ "$cur_mb" -ge $((want_mb * 95 / 100)) ] && echo 1 || echo 0)"
    ok_if "재부팅 뒤에도 스왑이 켜지도록 fstab에 있다" "$(succeeds grep -qE '^/swapfile[[:space:]]' /etc/fstab)"
  fi
}

check_docker() {
  echo "-- Docker"
  ok_if "docker가 설치돼 있다" "$(succeeds command -v docker)"
  ok_if "docker compose 플러그인이 있다" "$(succeeds docker compose version)"
  ok_if "docker buildx 플러그인이 있다(이미지 아키텍처 검사에 쓴다)" "$(succeeds docker buildx version)"
  ok_if "daemon.json이 설계대로다(로그 로테이션$([ "$ROLE" = app ] && echo ', live-restore'))" "$(succeeds cmp -s "$CONF/daemon-$ROLE.json" /etc/docker/daemon.json)"
  ok_if "docker 그룹이 있다" "$(succeeds getent group docker)"
  if skipped systemd; then skip "Docker 데몬 상태 (FIT_SKIP=systemd)"; else
    ok_if "Docker 데몬이 돌고 있다" "$(succeeds docker info)"
    if [ "$ROLE" = app ]; then ok_if "live-restore가 켜져 있다" "$(is "$(docker info --format '{{.LiveRestoreEnabled}}' 2>/dev/null)" true)"; fi
    ok_if "정리 타이머가 켜져 있다" "$(succeeds systemctl is-enabled --quiet fit-docker-prune.timer)"
  fi
  ok_if "정리 스크립트가 설치돼 있다" "$(file_is /usr/local/lib/fit/docker-prune.sh 755 root:root)"
  ok_if "정리 서비스·타이머 유닛이 설계대로다" \
    "$(is "$(succeeds cmp -s "$CONF/systemd/fit-docker-prune.service" /etc/systemd/system/fit-docker-prune.service)$(succeeds cmp -s "$CONF/systemd/fit-docker-prune.timer" /etc/systemd/system/fit-docker-prune.timer)" 11)"
  if [ "$ROLE" = app ]; then
    if skipped networks || skipped systemd; then skip "공유 Docker 망 (FIT_SKIP)"; else
      ok_if "공유 Docker 망이 있고 net-data만 internal이다" "$(succeeds bash "$HERE/networks.sh" check)"
    fi
  fi
}

check_dirs_and_accounts() {
  echo "-- 디렉터리와 계정"
  ok_if "/etc/fit이 root:docker 750이다" "$(file_is /etc/fit 750 root:docker)"
  ok_if "/etc/fit/keys가 root 700이다" "$(file_is /etc/fit/keys 700 root:root)"
  ok_if "/etc/fit/role이 역할과 같다" "$(is "$(cat /etc/fit/role 2>/dev/null)" "$ROLE")"
  if [ "$ROLE" = app ]; then
    ok_if "/srv/fit/state, web이 있다" "$(is "$(file_is /srv/fit/state 755 root:root)$(file_is /srv/fit/web 755 root:root)" 11)"
    ok_if "/srv/fit/backups가 root 700이다" "$(file_is /srv/fit/backups 700 root:root)"
    ok_if "fit-dev 계정은 셸이 없다" "$(is "$(getent passwd fit-dev | cut -d: -f7)" /usr/sbin/nologin)"
    ok_if "fit-dev의 authorized_keys가 있고 권한이 맞다" "$(is "$(file_is /home/fit-dev/.ssh 700 fit-dev:fit-dev)$(file_is /home/fit-dev/.ssh/authorized_keys 600 fit-dev:fit-dev)" 11)"
  else
    ok_if "vault 계정이 있다" "$(succeeds id vault)"
    ok_if "/srv/vault/incoming은 vault 전용 700이다" "$(file_is /srv/vault/incoming 700 vault:vault)"

check_ssh() {
  echo "-- SSH"
  ok_if "비밀번호 로그인이 꺼져 있다" "$(is "$(sshd_value ubuntu passwordauthentication)" no)"
  ok_if "키보드 대화형 로그인이 꺼져 있다" "$(is "$(sshd_value ubuntu kbdinteractiveauthentication)" no)"
  ok_if "root 로그인이 꺼져 있다" "$(is "$(sshd_value root permitrootlogin)" no)"
  ok_if "공개키 로그인이 켜져 있다" "$(is "$(sshd_value ubuntu pubkeyauthentication)" yes)"
  ok_if "SSH 포트가 22다" "$(is "$(sshd -T 2>/dev/null | awk '$1 == "port" { print $2; exit }')" 22)"
  if [ "$ROLE" = app ]; then
    ok_if "fit-dev는 터널만 된다(local 전달, 개발 포트 세 개, TTY 없음, 명령 고정)" \
      "$(is "$(sshd_value fit-dev allowtcpforwarding)|$(sshd_value fit-dev permitopen)|$(sshd_value fit-dev permittty)|$(sshd_value fit-dev forcecommand)" \
        'local|127.0.0.1:3000 127.0.0.1:8888 127.0.0.1:5432|no|/usr/sbin/nologin')"
    ok_if "일반 계정의 포트 전달은 막히지 않았다(관리자 터널용)" "$(is "$(sshd_value ubuntu allowtcpforwarding)" yes)"
  else
    ok_if "vault는 전달·TTY·사용자 rc가 막혀 있다" \
      "$(is "$(sshd_value vault allowtcpforwarding)|$(sshd_value vault permittty)|$(sshd_value vault permituserrc)" 'no|no|no')"
  fi
  if skipped systemd; then skip "fail2ban 상태 (FIT_SKIP=systemd)"; else
    ok_if "fail2ban이 돌고 sshd 감옥이 켜져 있다" "$(succeeds fail2ban-client status sshd)"
  fi
  ok_if "fail2ban 설정 검사가 통과한다" "$(succeeds fail2ban-client -t)"
  ok_if "fail2ban sshd 감옥이 설정돼 있다(재시도 5회, 1시간)" \
    "$(is "$(grep -cE '^(maxretry = 5|bantime = 1h|enabled = true)$' /etc/fail2ban/jail.d/fit.local 2>/dev/null)" 3)"
  if [ -n "${FIT_PEER_IP:-}" ]; then
    local ip all=1
    for ip in $FIT_PEER_IP; do
      sed -n 's/^ignoreip = //p' /etc/fail2ban/jail.d/fit.local 2>/dev/null | tr ' ' '\n' | grep -qxF "$ip" || all=0
    done
    ok_if "fail2ban이 상대 서버를 차단하지 않는다(ignoreip)" "$all"
  else
    skip "fail2ban ignoreip의 상대 서버 (FIT_PEER_IP 없음)"
  fi
  ok_if "자동 보안 업데이트는 켜져 있고 자동 재부팅은 꺼져 있다" \
    "$(is "$(apt-config dump 2>/dev/null | grep -cE '^(APT::Periodic::Unattended-Upgrade "1";|Unattended-Upgrade::Automatic-Reboot "false";)$')" 2)"
}

check_firewall() {
  echo "-- 방화벽과 열린 포트"
  local expected="ufw limit 22/tcp" added
  if [ "$ROLE" = app ]; then expected="$(printf 'ufw allow 443/tcp\nufw allow 80/tcp\nufw limit 22/tcp')"; fi
  added="$(ufw show added 2>/dev/null | grep '^ufw ' | sort)"
  ok_if "ufw 허용 규칙이 설계와 정확히 같다($([ "$ROLE" = app ] && echo '22 limit, 80, 443' || echo '22 limit'))" "$(is "$added" "$(printf '%s\n' "$expected" | sort)")"
  local status
  status="$(ufw status verbose 2>/dev/null)"
  ok_if "ufw가 켜져 있다" "$(is "$(printf '%s\n' "$status" | head -n 1)" 'Status: active')"
  ok_if "기본 정책은 들어오는 것 차단, 나가는 것 허용이다" "$(succeeds grep -q 'Default: deny (incoming), allow (outgoing)' <<<"$status")"
  # 외부에서 닿는 TCP 리스너(루프백이 아닌 주소)가 허용 포트뿐인가. Docker가 게시한 포트도 여기에 잡힌다
  local allowed=" 22 " bad="" port addr
  if [ "$ROLE" = app ]; then allowed=" 22 80 443 "; fi
  while read -r addr; do
    port="${addr##*:}"
    case "$addr" in 127.* | "[::1]:"* | "::1:"*) continue ;; esac
    case "$allowed" in *" $port "*) ;; *) bad="$bad $port" ;; esac
  done < <(ss -H -lnt 2>/dev/null | awk '{ print $4 }')
  if [ -z "$bad" ]; then pass "외부에 열린 TCP 포트가 허용 목록 안이다(${allowed# })"; else fail "허용 목록 밖에서 열린 TCP 포트:$bad"; fi
}

check_system
check_docker
check_dirs_and_accounts
check_ssh
check_firewall

if [ "$FAILED" -gt 0 ]; then
  printf '\n%d개 점검 실패\n' "$FAILED"
  exit 1
fi
printf '\n호스트 정상\n'
````

- [ ] **Step 2: bootstrap.sh 작성**

````bash
#!/usr/bin/env bash
# 서버 한 대를 설계 3절의 상태로 만든다. 몇 번 실행해도 같은 결과다(멱등). root로 실행한다.
#   sudo ROLE=app bash infra/host/bootstrap.sh    # 서버 A(Lightsail x86)
#   sudo ROLE=ops bash infra/host/bootstrap.sh    # 서버 B(EC2 Arm)
# 환경변수(선택)
#   FIT_PEER_IP      상대 서버의 공인 IP(공백으로 여러 개). fail2ban이 이 주소는 차단하지 않는다
#   FIT_SKIP         건너뛸 단계(쉼표로 구분, 시험용): docker-install, swap, sysctl-apply, systemd, networks
#   FIT_FORCE_SSH=1  키가 등록된 로그인 계정이 없어도 비밀번호 로그인을 끈다(서버에 못 들어갈 수 있다)
# 실행 전에 다른 터미널에서 키로 SSH 접속이 되는지 확인한다. 이 스크립트가 비밀번호 로그인을 끄기 때문이다.
# 확인은 infra/host/verify-host.sh가 한다.
set -euo pipefail

HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
CONF="$HERE/conf"
ROLE="${ROLE:-}"
SKIP=",${FIT_SKIP:-},"
CHANGES=0
PUT=0
TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT

step() { printf '\n== %s\n' "$*"; }
log() { printf '%s\n' "$*"; }
die() { printf 'FAIL %s\n' "$*" >&2; exit 1; }
skipped() { case "$SKIP" in *",$1,"*) log "건너뜀($1)"; return 0 ;; esac; return 1; }
changed() { CHANGES=$((CHANGES + 1)); log "변경: $*"; }

# put_file 원본 대상 모드 [소유자:그룹]: 내용, 모드, 소유자 중 하나라도 다르면 설치하고 PUT=1로 둔다
put_file() {
  local src="$1" dst="$2" mode="$3" owner="${4:-root:root}"
  PUT=0
  if [ -f "$dst" ] && cmp -s "$src" "$dst" && [ "$(stat -c %a "$dst")" = "$mode" ] && [ "$(stat -c %U:%G "$dst")" = "$owner" ]; then
    return 0
  fi
  install -D -m "$mode" -o "${owner%%:*}" -g "${owner##*:}" "$src" "$dst"
  PUT=1
  changed "$dst"
}

ensure_dir() { # ensure_dir 경로 모드 소유자:그룹
  if [ -d "$1" ] && [ "$(stat -c %a "$1")" = "$2" ] && [ "$(stat -c %U:%G "$1")" = "$3" ]; then return 0; fi
  install -d -m "$2" -o "${3%%:*}" -g "${3##*:}" "$1"
  changed "디렉터리 $1"
}

ensure_user() { # ensure_user 이름 셸. 비밀번호는 '*'라 키로만 들어온다(잠긴 계정은 sshd가 거부할 수 있다)
  if id "$1" >/dev/null 2>&1; then return 0; fi
  useradd --create-home --shell "$2" --password '*' "$1"
  changed "계정 $1"
}

preflight() {
  step "사전 확인"
  [ "$(id -u)" = 0 ] || die "root로 실행한다(sudo)"
  case "$ROLE" in app | ops) ;; *) die "ROLE=app 또는 ROLE=ops를 지정한다" ;; esac
  # shellcheck disable=SC1091
  . /etc/os-release
  [ "${ID:-}" = ubuntu ] || die "Ubuntu가 아니다"
  case "${VERSION_ID:-}" in
    22.04 | 24.04) ;;
    *) log "경고: 시험하지 않은 Ubuntu 버전이다(22.04와 24.04에서 시험했다)" ;;
  esac
  local want=x86_64
  if [ "$ROLE" = ops ]; then want=aarch64; fi
  [ "$(uname -m)" = "$want" ] || log "경고: ROLE=$ROLE은 $want 서버를 기대한다(설계 3절)"
  log "ROLE=$ROLE"
}

install_packages() {
  step "패키지"
  local pkgs=(ca-certificates curl gnupg tzdata rsync iproute2 openssh-server ufw fail2ban python3-systemd unattended-upgrades)
  local missing=() p
  for p in "${pkgs[@]}"; do
    dpkg -s "$p" >/dev/null 2>&1 || missing+=("$p")
  done
  if [ "${#missing[@]}" -gt 0 ]; then
    export DEBIAN_FRONTEND=noninteractive
    apt-get -o Acquire::Retries=3 update -qq
    apt-get -o Acquire::Retries=3 install -y -qq --no-install-recommends "${missing[@]}" >/dev/null
    changed "패키지 설치: ${missing[*]}"
  else
    log "그대로"
  fi
}

set_timezone() {
  step "시간대"
  local want=Asia/Seoul cur
  cur="$(readlink -f /etc/localtime 2>/dev/null || true)"
  if [ "${cur##*/zoneinfo/}" = "$want" ] && [ "$(cat /etc/timezone 2>/dev/null || true)" = "$want" ]; then
    log "그대로"
    return 0
  fi
  ln -sf "/usr/share/zoneinfo/$want" /etc/localtime
  echo "$want" >/etc/timezone
  changed "시간대 $want"
}

setup_swap() {
  step "스왑"
  skipped swap && return 0
  local want_mb=2048 cur_mb
  if [ "$ROLE" = app ]; then want_mb=4096; fi
  cur_mb="$(awk '/^SwapTotal:/ { print int($2 / 1024) }' /proc/meminfo)"
  if [ "$cur_mb" -ge $((want_mb * 95 / 100)) ]; then
    log "그대로(목표 ${want_mb}MB)"
  else
    if swapon --show=NAME --noheadings | grep -x /swapfile >/dev/null; then swapoff /swapfile; fi
    rm -f /swapfile
    fallocate -l "${want_mb}M" /swapfile || dd if=/dev/zero of=/swapfile bs=1M count="$want_mb" status=none
    chmod 600 /swapfile
    mkswap /swapfile >/dev/null
    swapon /swapfile
    changed "스왑 ${want_mb}MB"
  fi
  if [ -f /swapfile ] && ! grep -qE '^/swapfile[[:space:]]' /etc/fstab; then
    echo '/swapfile none swap sw 0 0' >>/etc/fstab
    changed "/etc/fstab의 스왑 항목"
  fi
}

  if [ "$ROLE" = app ]; then put_file "$CONF/sysctl-app.conf" /etc/sysctl.d/91-fit-app.conf 644; fi
  skipped sysctl-apply && return 0
  sysctl --system >/dev/null

}

install_docker() {

configure_docker() {

  if [ -f "$dst" ]; then prev="$TMP/10-fit.prev"; cp -p "$dst" "$prev"; fi
  mkdir -p /run/sshd
  put_file "$TMP/10-fit.conf" "$dst" 644
  if ! sshd -t; then

configure_ufw() {
  step "방화벽(ufw)"
  local port before after
  # awk가 먼저 끝나면 sshd가 SIGPIPE로 죽어 pipefail에 걸린다. 끝까지 읽는다
  port="$(sshd -T 2>/dev/null | awk '$1 == "port" && !seen { print $2; seen = 1 }')"
  [ "$port" = 22 ] || die "sshd가 22번 포트가 아니라 ufw가 SSH를 막을 수 있다(포트 ${port:-?}). 확인하고 다시 실행한다"
  before="$(ufw show added 2>/dev/null || true)"
  ufw default deny incoming >/dev/null
  ufw default allow outgoing >/dev/null
  ufw limit 22/tcp >/dev/null
  if [ "$ROLE" = app ]; then
    ufw allow 80/tcp >/dev/null
    ufw allow 443/tcp >/dev/null
  fi
  after="$(ufw show added 2>/dev/null || true)"
  if [ "$before" != "$after" ]; then changed "ufw 규칙"; fi
  ufw --force enable >/dev/null
  log "ufw 활성"
  # 목록에 없는 규칙은 지우지 않고 알려 준다(verify-host.sh가 실패로 보고한다)
  local extra
  extra="$(printf '%s\n' "$after" | grep '^ufw ' | grep -vE '^ufw (limit 22/tcp|allow 80/tcp|allow 443/tcp)$' || true)"
  if [ -n "$extra" ]; then
    log "경고: 허용 목록에 없는 ufw 규칙이 있다. 필요 없으면 'ufw delete'로 지운다:"
    printf '  %s\n' "$extra"
  fi
}
````

### Task 4: 컨테이너 시험

**목표:** Ubuntu 컨테이너에서 bootstrap과 verify-host를 실제로 적용·점검하고, 설정을 하나씩 망가뜨려 verify-host가 잡는지와 bootstrap이 고치는지를 확인한다.

**Files:**
- Create: `infra/host/test/run-in-container.sh`

**Interfaces:**
- `run-in-container.sh app|ops`: 컨테이너 안에서 도는 시험(`test-host.sh`가 `docker run`으로 부른다). 환경변수 `FIT_TEST_VERBOSE=1`이면 verify-host 출력을 전부 보여 준다. 시험 개수만큼 `PASS`·`FAIL`을 내고 마지막 줄이 `컨테이너 시험 통과(ROLE=…)`다.
- 컨테이너 조건: `--cap-add NET_ADMIN --cap-add NET_RAW`(ufw), `infra/host`를 `/opt/fit-host`에 읽기 전용으로 마운트한다.
- 컨테이너에서 건너뛰는 것: `FIT_SKIP=swap,sysctl-apply,systemd,networks`(B는 `arch`도). 이 단계들은 컨테이너에서 확인되지 않는다(커널 전역 설정은 이 PC의 Docker VM과 공유되고 systemd와 Docker 데몬이 없다).

시험이 확인하는 것:

- 잘못된 입력: ROLE 없음
- 적용: bootstrap 성공(첫 실행이 일시적으로 실패하면 한 번 더 실행), 두 번째 실행은 `변경 없음`, verify-host 통과, 출력에 IP·키 없음
- 설정 단위: 클라우드 이미지의 `PasswordAuthentication yes`보다 우리 설정이 먼저 적용됨, `daemon.json` JSON, Docker·compose·buildx 설치, 유닛 문법(`systemd-analyze verify`)
- 망가뜨리기(각각 verify-host가 실패하고 고친 뒤 통과): 허용 목록 밖 ufw 규칙, 비밀번호 로그인 켜기, 시간대, fail2ban 감옥 삭제, `daemon.json` 변경, `/etc/fit` 권한, 자동 재부팅 켜기, `fit-dev` 터널 제한 해제(A) 또는 `vault` 전달 허용(B), 허용 목록 밖 포트(2222) 열기
- 잠금 방지: 관리자 키가 없으면(터널 계정 `fit-dev`나 금고 계정 `vault`에 키가 있어도) SSH 하드닝을 거부하고 설정 파일을 만들지 않으며, 키를 되돌리면 다시 성공한다. `FIT_PEER_IP`에 명령 주입을 시도하면 거부한다
- 되돌리기: 깨진 SSH 설정이면 bootstrap이 멈추고 이전 파일로 되돌림

- [ ] **Step 1: 컨테이너 시험 작성**

````bash
#!/usr/bin/env bash
# Ubuntu 컨테이너 안에서 bootstrap.sh와 verify-host.sh를 시험한다. test-host.sh가 컨테이너를 띄워 부른다.
#   bash run-in-container.sh app|ops
# 컨테이너에는 systemd와 Docker 데몬, 커널 전역 설정(스왑, sysctl)이 없어서 FIT_SKIP으로 그 단계만 건너뛴다.
# 나머지(패키지, Docker 설치, 설정 파일, SSH, fail2ban, ufw, 계정, 디렉터리)는 실제로 적용하고 점검한다.
set -uo pipefail

ROLE="${1:?app 또는 ops}"
H=/opt/fit-host
SKIPS=swap,sysctl-apply,systemd,networks
# 시험 컨테이너는 x86이라 B(Arm)의 CPU 구조 점검은 건너뛴다
if [ "$ROLE" = ops ]; then SKIPS="$SKIPS,arch"; fi
export ROLE FIT_SKIP="$SKIPS" FIT_PEER_IP="203.0.113.7 198.51.100.9"

FAILED=0
pass() { printf 'PASS  %s\n' "$1"; }
fail() {
  printf 'FAIL  %s\n' "$1"
  FAILED=$((FAILED + 1))
  # 실패한 점검 바로 앞에 캡처한 출력(변수 out)의 끝부분을 보여 줘서 원인을 알 수 있게 한다
  if [ -n "${out:-}" ]; then printf '%s\n' "$out" | tail -n 12 | sed 's/^/FAIL  > /'; fi
}
ok_if() { if [ "$2" = 1 ]; then pass "$1"; else fail "$1"; fi; }
has() { case "$1" in *"$2"*) echo 1 ;; *) echo 0 ;; esac; }
bootstrap() { bash "$H/bootstrap.sh" 2>&1; }
verify() { bash "$H/verify-host.sh" 2>&1; }

export DEBIAN_FRONTEND=noninteractive
apt-get update -qq >/dev/null 2>&1
# 클라우드 이미지처럼 비밀번호 로그인을 켜는 파일이 있어도 우리 설정이 이겨야 한다
mkdir -p /etc/ssh/sshd_config.d
printf 'PasswordAuthentication yes\n' >/etc/ssh/sshd_config.d/60-cloudimg-settings.conf

echo "--- 잘못된 입력"
out="$(ROLE='' bash "$H/bootstrap.sh" 2>&1)"; rc=$?
ok_if "ROLE이 없으면 거부한다" "$([ "$rc" != 0 ] && [ "$(has "$out" 'ROLE=app 또는 ROLE=ops')" = 1 ] && echo 1 || echo 0)"

echo "--- 관리자 키를 등록하고 적용"
# Ubuntu 24.04 이미지에는 ubuntu 계정이 이미 있고 22.04 이미지에는 없다
id ubuntu >/dev/null 2>&1 || useradd --create-home --shell /bin/bash ubuntu
install -d -m 700 -o ubuntu -g ubuntu /home/ubuntu/.ssh
KEYLINE='ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA test@example'
echo "$KEYLINE" >/home/ubuntu/.ssh/authorized_keys
chown ubuntu:ubuntu /home/ubuntu/.ssh/authorized_keys
chmod 600 /home/ubuntu/.ssh/authorized_keys
out="$(bootstrap)"; rc=$?
if [ "$rc" != 0 ]; then
  # 패키지 내려받기가 일시적으로 실패했을 수 있다. bootstrap은 멱등이라 한 번 더 실행한다
  echo "(첫 실행이 실패해 한 번 더 실행한다)"
  printf '%s\n' "$out" | tail -n 5
  out="$(bootstrap)"; rc=$?
fi
printf '%s\n' "$out" | tail -n 4
ok_if "bootstrap이 성공한다" "$([ "$rc" = 0 ] && echo 1 || echo 0)"
out="$(bootstrap)"; rc=$?
ok_if "다시 실행하면 변경이 없다(멱등)" "$([ "$rc" = 0 ] && [ "$(has "$out" '변경 없음')" = 1 ] && echo 1 || echo 0)"
out="$(verify)"; rc=$?
if [ -n "${FIT_TEST_VERBOSE:-}" ]; then
  printf '%s\n' "$out"
else
  printf '%s\n' "$out" | grep -E '^(FAIL|SKIP)|개 점검|호스트 정상' || true
fi
ok_if "verify-host가 통과한다" "$([ "$rc" = 0 ] && echo 1 || echo 0)"
ok_if "verify-host가 IP와 키 값을 출력하지 않는다" "$([ "$(has "$out" 203.0.113.7)$(has "$out" AAAAC3Nza)" = 00 ] && echo 1 || echo 0)"

echo "--- 설정 단위 확인"
ok_if "클라우드 이미지의 설정보다 우리 SSH 설정이 먼저 적용된다" \
  "$([ "$(sshd -T -C user=ubuntu,host=h,addr=192.0.2.1 | awk '$1 == "passwordauthentication" { print $2 }')" = no ] && echo 1 || echo 0)"
ok_if "daemon.json이 올바른 JSON이다" "$(python3 -c 'import json; json.load(open("/etc/docker/daemon.json"))' 2>/dev/null && echo 1 || echo 0)"
ok_if "Docker가 설치됐다" "$(docker --version >/dev/null 2>&1 && docker compose version >/dev/null 2>&1 && docker buildx version >/dev/null 2>&1 && echo 1 || echo 0)"
if apt-get install -y -qq systemd >/dev/null 2>&1; then
  ok_if "정리 타이머 유닛 문법이 맞다(systemd-analyze verify)" \
    "$(systemd-analyze verify /etc/systemd/system/fit-docker-prune.service /etc/systemd/system/fit-docker-prune.timer >/dev/null 2>&1 && echo 1 || echo 0)"
fi

echo "--- 잠금 방지: 관리자 키가 없으면 비밀번호 로그인을 끄지 않는다"
````

````markdown
# 호스트 (bootstrap)

서버 A(`app`, Lightsail x86)와 B(`ops`, EC2 Arm)를 설계 3절의 상태로 만들고 점검한다. 설계는 [design.md](../../docs/infra/design.md) 3절이다. Ubuntu 22.04와 24.04에서 시험했다.

## 서버에서 하는 순서

1. 관리자 계정으로 키 SSH 접속이 되는지 **다른 터미널에서 먼저 확인**한다. bootstrap이 비밀번호 로그인을 끈다.
2. `infra/host/` 디렉터리를 서버로 복사한다(`scp -r infra/host <서버>:~/host`). 이 디렉터리만 있으면 된다.
3. 설계 3.1절의 Day-0 실측을 돌리고 결과를 붙여 준다.
4. 적용한다. `FIT_PEER_IP`에는 상대 서버(A면 B, B면 A)의 공인 IP를 넣는다.

   ```bash
   sudo ROLE=app FIT_PEER_IP=<B의 공인 IP> bash ~/host/bootstrap.sh   # 서버 A
   sudo ROLE=ops FIT_PEER_IP=<A의 공인 IP> bash ~/host/bootstrap.sh   # 서버 B
   ```

5. 점검한다. 전부 PASS여야 한다: `sudo bash ~/host/verify-host.sh`
6. 서버 밖(노트북)에서 포트를 확인한다: `Test-NetConnection <호스트> -Port 22`(열림), `80`, `443`(Caddy 전에는 닫힘). 클라우드 방화벽(Lightsail 네트워킹 탭, EC2 보안 그룹)도 같은 포트만 열려 있는지 사람이 본다.

| `test/` | 노트북 시험(Ubuntu 컨테이너와 이 PC의 Docker) |

## bootstrap의 안전장치

- **잠금 방지:** 키가 등록된 일반 로그인 계정이 없으면 비밀번호 로그인을 끄지 않고 멈춘다. sshd 설정 검사(`sshd -t`)가 실패하면 이전 파일로 되돌린다. sshd가 22번 포트가 아니면 ufw를 건드리지 않고 멈춘다.
- **ufw:** 22는 허용 규칙을 먼저 넣은 뒤 켠다. 허용 목록 밖의 기존 규칙은 지우지 않고 알려 주기만 한다(verify-host가 실패로 보고한다).
- **Docker:** 이미 설치돼 있으면 건드리지 않는다. 기존 `daemon.json`은 한 번만 `.fit-orig`로 백업한다. 컨테이너가 돌고 있으면 Docker를 재시작하지 않는다.
- **fail2ban:** `FIT_PEER_IP`를 `ignoreip`에 넣어 A와 B 사이 전송이 차단되지 않게 한다. IP가 아닌 값은 거부한다.

## 환경변수

| 이름 | 뜻 |
|---|---|
| `ROLE` | `app` 또는 `ops`(bootstrap 필수. verify-host는 `/etc/fit/role`에서 읽는다) |
| `FIT_PEER_IP` | 상대 서버의 공인 IP(공백으로 여러 개) |
| `FIT_FORCE_SSH=1` | 키가 없어도 비밀번호 로그인을 끈다. 서버에 못 들어갈 수 있다 |
| `FIT_SKIP` | 건너뛸 단계(쉼표): `docker-install`, `swap`, `sysctl-apply`, `systemd`, `networks`, `arch`(verify-host만). 시험용이다 |
| `FIT_NET_PREFIX` | `networks.sh`의 망 이름 앞에 붙일 접두사(시험용) |
````
