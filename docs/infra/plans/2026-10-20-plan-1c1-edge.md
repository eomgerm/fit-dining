# 엣지(Caddy) 구현 계획 (Plan 1C-1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버 A의 엣지(Caddy)를 만든다. 호스트(`PROD_HOST`, `DEV_HOST`)로 prod와 dev를 나누고, Next.js(SSR) FE와 BE를 활성 색으로 프록시한다. 정적 자산 누적 풀, dev 쿠키 게이트, 사진 업로드·읽기 프록시, 인증서 단계 전환, 로그·메트릭을 설정으로 정의한다. 운영 명령(`edgectl.sh`)과 점검 스크립트, 서버 없이 노트북에서 실제로 띄워 시험하는 환경을 함께 만든다.

**Architecture:** `infra/edge/conf/Caddyfile` 하나가 호스트별 사이트 둘을 정의하고, 환경별 라우팅은 `{args[0]}`을 받는 스니펫 `env_routes` 한 곳을 prod와 dev가 함께 쓴다. 인증서 단계(`ACME_MODE`)와 HSTS(`HSTS_MODE`)는 환경변수가 고르는 조각 파일로 바꾼다. 활성 색은 배포 스크립트가 쓰는 서비스별 상태 파일 `/srv/fit/state/upstream-<환경>-<be|fe>.caddy`를 import해서 정한다. FE 서버가 BE를 부를 때는 Caddy의 내부 리스너(`:8081` prod, `:8082` dev)를 거쳐 활성 색을 Caddy 한 곳이 고른다. 노트북 시험 환경(`infra/edge/test/`)은 목 BE·FE, 시험용 정적 자산 풀, 1B 로컬 스택의 실제 garage를 붙인다.

**Tech Stack:** Caddy 2.11.7, Docker Compose v2(2.24 이상, `!override` 사용), bash, curl 7.75 이상, python 3.9 이상(스트리밍 측정)과 python 3.12 이미지(목 BE·FE).

**Spec:** [docs/infra/design.md](../design.md) (5절 엣지·TLS, 6.8절 프런트(Next.js SSR), 12.5절 프런트 계약, 13.2절 시크릿)

| `edgectl.sh status` | 활성 색과 컨테이너 상태를 한 번에 본다 |
| `verify-edge.sh --resolve` | DNS를 바꾸기 전에 서버만 점검할 수 있다 |
| `test-edge.sh`가 서버와 같은 `reload` 경로를 쓴다 | 시험한 절차가 곧 운영 절차다. 노트북에서 전환, 롤백, 실패 상황을 미리 해 볼 수 있다 |
| 캐시 헤더는 FE가 정하고 Caddy는 정적 자산만 `immutable`을 붙인다 | HTML·RSC의 캐시 정책을 FE 코드 한 곳에서 바꾼다 |

## 검증 결과

이 계획의 코드는 저장소를 clone한 임시 복사본(저장소 밖)에서 계획의 코드 블록만으로 다시 만들어 실행해 확인했다.

- 러너는 모든 단계가 통과하고(be의 Dockerfile이 없어 건너뛰는 단계와, 복사본에 `origin/master`가 없어 건너뛴 `history` 제외) 자가 테스트 10종이 통과한다. `lint:caddy`의 스크립트 줄을 핀한 이미지(`caddy:2.11.7`)에서 실행해도 통과한다.
- 노트북 시험 환경(`test-edge.sh`)은 빈 상태에서 켜서 `verify-edge.sh`와 동작 시험이 모두 통과한다(`PASS` 102개, `FAIL` 0개). 같은 `verify`를 다시 돌려도 통과하고, 잘못된 dev 키나 닿지 않는 주소를 주면 실패한다. 연속 세 번 실행해 모두 통과했다.
- 시험이 죽은 검사가 아닌지 확인하려고 실행 중인 엣지의 Caddyfile을 8곳 망가뜨려 보았다(`X-Powered-By` 제거 삭제, 풀 경로 무력화, 게이트 쿠키 지우기 삭제, 본문 한도 2MB→20MB, manifest의 게이트 제외 삭제, 로그의 `k` 삭제 무력화, garage 웹 호스트 지정 삭제, `/photos` 접두사 제거 삭제). 모든 변형에서 `verify`가 해당 항목을 실패로 잡았다.
- 호스트 분리: `localhost`(prod)와 `dev.localhost`(dev)가 같은 443에서 호스트로 나뉘고 Caddy 내부 CA가 둘 다 인증서를 발급한다. dev의 쿠키에는 `Domain`이 없다.
- 인증서 단계: `ACME_MODE=staging`은 staging 이슈어 하나만, `production`은 Let's Encrypt와 ZeroSSL 둘을 가진 설정이 된다(`caddy adapt` 결과). 그래서 운영 단계에서 `acme_ca`를 지정하지 않는다.
- 정적 자산 풀: 풀에 있는 `/_next/static/*`는 FE를 거치지 않고 Caddy가 `immutable`로 준다. 풀에 없으면 FE가 대신 응답하고 어디에도 없으면 404(`immutable` 아님)다. `..` 경로로 풀 밖의 파일을 읽을 수 없다. dev와 prod 풀은 분리돼 있다.
- SSR: `encode zstd gzip`가 켜진 상태에서 스트리밍 응답의 첫 덩어리가 1.5초 뒤의 마지막 덩어리를 기다리지 않고 도착한다(첫 바이트 0.02초, 전체 1.52초). 목 FE가 보낸 `Server`·`X-Powered-By` 헤더는 지워지고 FE의 `Cache-Control`은 바뀌지 않는다.
- 전환: 상태 파일만 바꾸면 트래픽은 그대로고 `edgectl.sh reload` 뒤에 옮겨진다. BE와 FE는 따로 전환되고, FE 서버가 내부 리스너로 읽는 BE 색은 FE 재시작 없이 바뀐다. reload 중 compose 망 안의 요청 150건이 모두 성공한다. 문법이 틀린 상태 파일은 `check`와 `reload`가 거부하고 직전 설정이 유지된다. 문법은 맞지만 없는 호스트를 가리키는 upstream은 둘 다 통과해서 요청이 502가 된다. 그래서 reload 뒤 스모크가 필요하다(계획 1C-2).
- dev 게이트: 통과한 요청에서 게이트 쿠키는 BE·FE로 전달되지 않고 다른 쿠키는 그대로 전달된다. 로그에는 쿼리의 `k`도 쿠키의 키도 남지 않는다.
- 사진 경로: 헤더 서명(SigV4) PUT이 엣지를 거쳐 로컬 garage에서 통과한다(Host 보존, prod와 dev 모두). 서명 없는 GET은 403, 웹 엔드포인트의 `confirmed/`는 공개 읽기(200, `Cache-Control: public`), `pending/`은 404, 10MB 초과 업로드는 413이다. 호스트마다 다른 환경의 버킷 경로는 garage로 가지 않는다.
- 본문 한도: 2MB 초과 `/api` 요청은 413이다. 본문을 읽지 않는 upstream은 한도를 넘기 전에 응답을 먼저 돌려줘서 한도가 드러나지 않으므로, 시험의 목 BE는 본문을 끝까지 읽는다.
- 메트릭 `:9180/metrics`는 compose 망 안에서 응답하고 호스트에는 게시되지 않는다. 관리 API(2019)와 내부 리스너(8081, 8082)도 호스트에 게시되지 않는다.
- Caddy의 `servers` 안 `metrics` 옵션은 폐기 예정이라 전역 `metrics`를 쓴다.
- `curl -o /dev/null`은 Git Bash의 Windows용 curl에서 쓰기 오류가 나서 스크립트는 상태 코드를 `-w`로 받는다. Docker Desktop(Windows)의 포트 포워더는 새 연결을 200건에 한 건쯤 거부했다. curl의 `--retry`는 이 오류를 재시도하지 않아서 시험 스크립트가 연결 실패(종료 코드 7)만 직접 다시 시도한다. compose 망 안의 요청은 거부되지 않았다. `curl --aws-sigv4`는 `-H`로 준 헤더를 서명 대상에 넣으므로 시험은 게이트 쿠키를 `-b`로 보낸다.

아래 코드를 그대로 옮기면 같은 결과가 나와야 한다. 다르면 코드를 고치기 전에 원인을 먼저 확인한다.

**아직 확인하지 못한 것**

- 실제 ACME 발급(호스트 둘, staging과 production)과 `HSTS_MODE=on` 이후의 동작. 서버에서 80 도달과 DNS가 필요하다(M1).
- 실제 Next.js(standalone)와의 연동. 시험은 목 FE로 했다. 실제 FE가 보내는 헤더(`Cache-Control`, 없는 `/_next/static` 요청의 404 응답), RSC 스트리밍, `/config.json`·`/fe-healthz` 구현은 프런트 팀 합의(12.5절)와 `verify-edge.sh` 실행으로 확인한다.
- 실제 BE(Spring)와의 연동. 프록시 헤더 처리(`server.forward-headers-strategy`)와 `/healthz`는 목 BE로만 확인했다.
- 실제 도메인에서의 동작. 시험은 `localhost`와 `dev.localhost`(Caddy 내부 CA)라서 공개 CA 발급과 DNS 경로는 시험하지 못했다.
- presigned URL과 POST policy 업로드, 브라우저가 보내는 Cookie와 서명의 관계, garage 수명주기(설계 7.4절의 서버 스파이크).
- Linux 서버의 포트 게시와 ufw, Mac·Linux에서의 시험 환경 실행, 메모리 한도 150m의 실측.
- iOS 홈 화면 PWA가 `?k=`로 받은 쿠키를 유지하는지(설계 5.4절).

## Global Constraints

1A·1B의 전역 제약이 모두 적용된다([plan 1A](2026-10-15-plan-1a-foundation-guardrails.md), [plan 1B](2026-10-19-plan-1b-local-env-contracts.md)). 이 계획에서 더 지키는 것은 다음과 같다.

- Caddy 파일(`Caddyfile`, `*.caddy`)은 탭으로 들여쓰고 `caddy fmt`가 바꾸지 않는 형태여야 한다.

- 시험용 값(`DEV_GATE_KEY` 등)은 엔트로피가 낮은 값이라 시크릿 검사에 걸리지 않는다. 서버 값으로 쓰지 않는다.
- 검증용 시험 환경은 `fit-edge-test`, `fit-edge-test-local` 프로젝트로 띄우고 `down`으로 지운다(이름 패턴 일괄 삭제 금지).
- 커밋 메시지와 브랜치는 1B와 같은 규칙이다. 브랜치는 `infra/feat/edge-caddy-S15P31A302-19`다.

### Task 2: Caddy 설정과 상태 파일 견본

**목표:** 호스트별 사이트, 라우팅, dev 게이트, 정적 자산 풀, 인증서·HSTS 단계, 로그, 메트릭을 Caddyfile로 정의한다.

**Files:**
- Create: `infra/edge/conf/Caddyfile`
- Create: `infra/edge/conf/acme/production.caddy`, `infra/edge/conf/acme/staging.caddy`
- Create: `infra/edge/conf/hsts/off.caddy`, `infra/edge/conf/hsts/on.caddy`
- Create: `infra/edge/state-sample/upstream-prod-be.caddy`, `upstream-prod-fe.caddy`, `upstream-dev-be.caddy`, `upstream-dev-fe.caddy`
- Modify: `.editorconfig`

**Interfaces:**
- 환경변수: `PROD_HOST`, `DEV_HOST`, `ACME_EMAIL`, `ACME_MODE`, `HSTS_MODE`, `DEV_GATE_KEY`(Task 1)
- 경로 계약: 정적 자산 풀 `/srv/fit/web/<env>/pool/_next/static/…`(URL 경로 그대로), 상태 `/srv/fit/state/upstream-<env>-<be|fe>.caddy`, garage `garage:3900`(S3 API), `garage:3902`(웹 엔드포인트, 웹 루트 도메인 `web.garage.localhost`)
- 라우팅(환경 공통, `env_routes`): `/_next/static/*`(풀 우선, 없으면 FE), `/api/*`(본문 2MB), `/healthz`, `/fit-<env>-photos/*`(본문 10MB, garage S3), `/photos/<env>/confirmed/*`(garage 웹), 그 외 `/photos/*`는 404, 나머지는 FE
- 내부 리스너: `:8081`(prod)·`:8082`(dev)는 활성 색 BE로, `:9180`은 메트릭이다. 호스트에 게시하지 않는다.

핵심 결정:

- 호스트마다 인증서를 따로 받고 둘 다 443이다. 쿠키·서비스 워커·localStorage는 호스트(출처)별로 분리된다.
- `/_next/static/*`는 풀에 파일이 있을 때만 Caddy가 `immutable`로 직접 서빙하고, 없으면 FE로 보낸다. 해시 자산을 정규식으로 알아보지 않는다(Next의 실제 자산 이름은 base36이라 16진수 규칙이 맞지 않는다). HTML·RSC·`public/` 파일의 캐시 헤더는 FE가 정하고 Caddy는 바꾸지 않는다.
- `ACME_MODE=staging`은 `acme_ca` 하나를 지정해 그 CA만 쓰고, `production`은 지정하지 않아 기본 이슈어 둘을 쓴다.
- dev 게이트는 쿠키 값이 `DEV_GATE_KEY`와 같을 때만 연다. `/?k=<키>`가 쿠키를 발급하고 `/`로 보낸다. 키는 영문자·숫자·`_`·`-`만 쓴다(쿠키와 정규식에 안전해야 한다). 게이트를 통과한 요청은 이 쿠키를 지운 뒤 프록시해서 키가 앱 컨테이너에 닿지 않는다. 쿠키는 `Domain` 없이 호스트 전용이다.
- 활성 색을 고르는 곳은 상태 파일뿐이다. 외부 경로(`/api`, FE)와 내부 리스너가 같은 파일을 import한다.

````bash
#!/usr/bin/env bash
# 서버 A에서 엣지(Caddy)를 다루는 명령 모음. 상태 확인, 설정 검사, 무중단 reload를 한 곳에 모은다.
# 배포 스크립트도 같은 reload를 쓴다(활성 색을 바꾼 뒤 한 줄로 적용).
#   bash infra/edge/edgectl.sh status   # 컨테이너 상태와 활성 색(Caddy가 보는 upstream 상태 파일)
#   bash infra/edge/edgectl.sh check    # 실행 중인 caddy 안에서 설정 문법을 검사한다
#   bash infra/edge/edgectl.sh reload   # check를 통과했을 때만 reload한다. 이어서 verify-edge.sh로 확인한다
# compose는 FIT_EDGE_ENV(기본 /etc/fit/edge.env)를 읽는다. 시험 환경은 FIT_EDGE_COMPOSE_ARGS로 compose 인자를 통째로 바꾼다.
set -euo pipefail

DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
if [ -n "${FIT_EDGE_COMPOSE_ARGS:-}" ]; then
  read -r -a DC <<<"docker compose $FIT_EDGE_COMPOSE_ARGS"
else
  DC=(docker compose --env-file "${FIT_EDGE_ENV:-/etc/fit/edge.env}" -f "$DIR/compose.edge.yml")
fi
CADDYFILE=/etc/caddy/Caddyfile

caddy_exec() { "${DC[@]}" exec -T caddy "$@"; }

check() {
  if caddy_exec caddy validate --config "$CADDYFILE" --adapter caddyfile >/dev/null 2>&1; then
    echo "OK 설정 문법"
  else
    echo "FAIL 설정 문법이 틀렸다. 자세한 내용: bash infra/edge/edgectl.sh check-verbose" >&2
    return 1
  fi
}

status() {
  "${DC[@]}" ps caddy
  echo
  echo "활성 색(Caddy가 보는 상태 파일)"
  # 파일 안의 reverse_proxy 대상만 뽑는다. 형식: <환경> <서비스> <호스트:포트>
  caddy_exec sh -c 'grep -H "^reverse_proxy " /srv/fit/state/upstream-*.caddy' |
    sed -E 's#^.*/upstream-([a-z]+)-([a-z]+)\.caddy:reverse_proxy ([^ ]+).*#\1 \2 \3#' |
    while read -r env svc target; do printf '  %-5s %-3s %s\n' "$env" "$svc" "$target"; done
}

reload() {
  check
  caddy_exec caddy reload --config "$CADDYFILE" --adapter caddyfile >/dev/null 2>&1
  echo "OK reload 완료. 없는 호스트를 가리키는 upstream은 reload를 통과하므로 verify-edge.sh로 확인한다"
}

case "${1:-}" in
  status) status ;;
  check) check ;;
  check-verbose) caddy_exec caddy validate --config "$CADDYFILE" --adapter caddyfile ;;
  reload) reload ;;
  *) echo "사용: bash infra/edge/edgectl.sh status | check | check-verbose | reload" >&2; exit 2 ;;
esac
````

````bash
#!/usr/bin/env bash
# 엣지의 라우팅·캐시·헤더·dev 게이트를 HTTP로 점검한다(설계 5.5절). 서버 안에서도, 노트북의 시험 환경(test/test-edge.sh)에서도 쓴다.
#   bash infra/edge/verify-edge.sh --prod https://호스트 [--dev https://dev호스트 --dev-key 키] [--http http://호스트]
#                                  [--resolve 호스트:포트:IP]... [--retry N] [--insecure]
# 각 점검은 PASS, FAIL, SKIP으로 출력하고 하나라도 FAIL이면 종료 코드 1이다. 키 값은 출력하지 않는다.
# --resolve는 curl의 같은 옵션이다. DNS를 바꾸기 전에 서버를 점검할 때 쓴다(예: --resolve fit.example.com:443:<서버 IP>).
# --retry N은 연결에 실패한 요청(curl 종료 코드 7)을 1초 간격으로 N번까지 다시 시도한다. 기본은 재시도 없음이다.
# 필요한 것: bash 3.2 이상, curl, 점검 대상에 배포된 FE(SSR 페이지, /config.json, /fe-healthz, /sw.js, /manifest.webmanifest)
set -u

PROD="" DEV="" DEV_KEY="" HTTP_URL="" INSECURE=0 RETRY=0
RESOLVE=()
while [ "$#" -gt 0 ]; do
  case "$1" in
    --prod) PROD="$2"; shift 2 ;;
    --dev) DEV="$2"; shift 2 ;;
    --dev-key) DEV_KEY="$2"; shift 2 ;;
    --http) HTTP_URL="$2"; shift 2 ;;
    --resolve) RESOLVE+=(--resolve "$2"); shift 2 ;;
    --retry) RETRY="$2"; shift 2 ;;
    --insecure) INSECURE=1; shift ;;
    *) echo "알 수 없는 인자: $1" >&2; exit 2 ;;
  esac
done

  exit 2

CURL=(curl -sS --max-time 20)

if [ "${#RESOLVE[@]}" -gt 0 ]; then CURL+=("${RESOLVE[@]}"); fi

FAILED=0
pass() { printf 'PASS  %s\n' "$1"; }
fail() { printf 'FAIL  %s\n' "$1"; FAILED=$((FAILED + 1)); }
skip() { printf 'SKIP  %s\n' "$1"; }

# fetch URL [curl 인자...]: STATUS, HEADERS(소문자), BODY를 채운다. 리다이렉트는 따라가지 않는다.
STATUS="" HEADERS="" BODY=""
fetch() {
  local raw rc tries=0
  while :; do
    rc=0
    raw="$("${CURL[@]}" -i "$@")" || rc=$?
    if [ "$rc" = "7" ] && [ "$tries" -lt "$RETRY" ]; then tries=$((tries + 1)); sleep 1; continue; fi
    break
  done
  if [ "$rc" != "0" ]; then STATUS="000"; HEADERS=""; BODY=""; return; fi
  raw="$(printf '%s' "$raw" | tr -d '\r')"
  STATUS="$(printf '%s\n' "$raw" | head -n 1 | awk '{print $2}')"
  HEADERS="$(printf '%s\n' "$raw" | awk 'NR > 1 { if ($0 == "") exit; print }' | tr '[:upper:]' '[:lower:]')"
  BODY="$(printf '%s\n' "$raw" | awk 'f { print } /^$/ && !f { f = 1 }')"
}
header_value() { printf '%s\n' "$HEADERS" | awk -F': ' -v k="$1" 'tolower($1) == k { sub(/^[^:]*: /, ""); print; exit }'; }
expect() { # expect NAME 조건(참이면 통과)
  if [ "$2" = "1" ]; then pass "$1"; else fail "$1 (status=$STATUS)"; fi
}
is() { if [ "$1" = "$2" ]; then echo 1; else echo 0; fi; }
has() { case "$1" in *"$2"*) echo 1 ;; *) echo 0 ;; esac; }

check_site() { # check_site 라벨 URL [curl 인자...]
  local label="$1" base="$2" asset
  shift 2
  fetch "$base/" "$@"
  expect "$label: / 는 200 + text/html(SSR 페이지)" "$(is "$STATUS$(has "$(header_value content-type)" text/html)" 2001)"
  expect "$label: nosniff 헤더" "$(is "$(header_value x-content-type-options)" nosniff)"
  expect "$label: Server 헤더 없음" "$(is "$(header_value server)" "")"
  expect "$label: X-Powered-By 헤더 없음" "$(is "$(header_value x-powered-by)" "")"
  expect "$label: h3(Alt-Svc) 광고 없음" "$(is "$(header_value alt-svc)" "")"
  asset="$(printf '%s\n' "$BODY" | grep -oE '/_next/static/[A-Za-z0-9_./%-]+\.js' | head -n 1)"
  for f in /fe-healthz /sw.js /manifest.webmanifest /healthz; do
    fetch "$base$f" "$@"
    expect "$label: $f 는 200" "$(is "$STATUS" 200)"
  done
  fetch "$base/config.json" "$@"
  expect "$label: /config.json 은 200 + env 키" "$(is "$STATUS$(has "$BODY" '"env"')" 2001)"
  if [ -n "$asset" ]; then
    fetch "$base$asset" "$@"
    expect "$label: 정적 자산 $asset 는 immutable" "$(is "$STATUS$(has "$(header_value cache-control)" immutable)" 2001)"
  else
    fail "$label: 첫 화면에서 /_next/static/ 아래의 .js를 찾지 못했다"
  fi
  fetch "$base/_next/static/chunks/no-such-file.0123abcd.js" "$@"
  expect "$label: 없는 정적 자산은 404" "$(is "$STATUS" 404)"
  expect "$label: 404 응답은 immutable이 아니다" "$(is "$(has "$(header_value cache-control)" immutable)" 0)"
  fetch "$base/photos/x/pending/a.jpg" "$@"
  expect "$label: /photos/ 아래 그 외 경로는 404" "$(is "$STATUS" 404)"
}

check_site prod "$PROD"

if [ -n "$HTTP_URL" ]; then
  fetch "$HTTP_URL/"
  expect "http→https 리다이렉트(3xx)" "$(has "301 302 307 308" "$STATUS")"
else
  skip "http→https 리다이렉트 (--http 없음)"
fi

if [ -n "$DEV" ] && [ -n "$DEV_KEY" ]; then
  for p in / /healthz /fe-healthz /api/v1/version /config.json /_next/static/chunks/app-1a2b3c4d.js; do
    fetch "$DEV$p"
    expect "dev: 쿠키 없이 $p 는 404" "$(is "$STATUS" 404)"
  done
  fetch "$DEV/manifest.webmanifest"
  expect "dev: /manifest.webmanifest 는 쿠키 없이 200(게이트 밖)" "$(is "$STATUS" 200)"
  fetch "$DEV/?k=wrong-key"
  expect "dev: 틀린 키는 404" "$(is "$STATUS" 404)"
  fetch "$DEV/?k=$DEV_KEY"
  cookie="$(header_value set-cookie)"
  expect "dev: 올바른 키는 302로 / 이동" "$(is "$STATUS$(header_value location)" 302/)"
  expect "dev: 쿠키 속성(Secure, HttpOnly, SameSite=Lax, Max-Age=1209600)" \
    "$(is "$(has "$cookie" secure)$(has "$cookie" httponly)$(has "$cookie" samesite=lax)$(has "$cookie" max-age=1209600)" 1111)"
  expect "dev: 쿠키 이름은 fit_dev" "$(has "$cookie" "fit_dev=")"
  expect "dev: 쿠키에 Domain 속성이 없다(호스트 전용)" "$(is "$(has "$cookie" "domain=")" 0)"
  check_site dev "$DEV" -H "Cookie: fit_dev=$DEV_KEY"
  fetch "$DEV/" -H "Cookie: fit_dev=wrong-key"
  expect "dev: 틀린 쿠키는 404" "$(is "$STATUS" 404)"
else
  skip "dev 게이트 (--dev, --dev-key 없음)"
fi

if [ "$FAILED" -gt 0 ]; then
  printf '\n%d개 점검 실패\n' "$FAILED"
  exit 1
fi
printf '\n엣지 정상\n'
````

````python
"""시험용 목 BE·FE(infra/edge/test). MOCK_KIND(be, fe)와 MOCK_NAME(blue, green, dev)으로 정해진다.

실제 서비스를 흉내 내는 최소한만 한다: 헬스, 색 표시, 받은 헤더 되돌리기, 본문 끝까지 읽기,
FE의 스트리밍 응답과 서버 쪽 BE 호출(BE_INTERNAL_URL).
"""
import os
import time
import urllib.request
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

KIND = os.environ["MOCK_KIND"]
NAME = os.environ["MOCK_NAME"]
APP_ENV = os.environ.get("APP_ENV", "dev")
BE_INTERNAL_URL = os.environ.get("BE_INTERNAL_URL", "")
PORT = 3000 if KIND == "fe" else 8080

PAGE = (
    '<!doctype html><html><head><link rel="manifest" href="/manifest.webmanifest">'
    '<script src="/_next/static/chunks/app-1a2b3c4d.js" defer></script>'
    '<script src="/_next/static/chunks/fe-only.js" defer></script></head>'
    "<body>mock-fe {name} {env}</body></html>"
)


class Handler(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"

    def reply(self, status, body, ctype="text/plain; charset=utf-8", headers=()):
        data = body.encode()
        self.send_response(status)
        self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(data)))
        if KIND == "fe":
            self.send_header("X-Powered-By", "Next.js")  # Caddy가 지우는지 본다
        for key, value in headers:
            self.send_header(key, value)
        self.end_headers()
        self.wfile.write(data)

    def echo(self):
        return "\n".join(
            [
                f"name={NAME}",
                f"cookie={self.headers.get('Cookie', '')}",
                f"xff={self.headers.get('X-Forwarded-For', '')}",
                f"proto={self.headers.get('X-Forwarded-Proto', '')}",
                f"host={self.headers.get('Host', '')}",
            ]
        )

    def drain_body(self):
        remaining = int(self.headers.get("Content-Length", 0))
        while remaining > 0:
            chunk = self.rfile.read(min(65536, remaining))
            if not chunk:
                break
            remaining -= len(chunk)

    def do_POST(self):
        self.drain_body()
        self.reply(200, "ok")

    do_PUT = do_POST

    def do_GET(self):
        path = self.path.split("?", 1)[0]
        if KIND == "be":
            self.be(path)
        else:
            self.fe(path)

    def be(self, path):
        if path == "/healthz":
            self.reply(200, f"ok {NAME}")
        elif path == "/api/v1/version":
            self.reply(200, f'{{"color":"{NAME}"}}', "application/json", [("X-App-Version", NAME)])
        elif path == "/api/echo":
            self.reply(200, self.echo())
        else:
            self.reply(404, "not found")

    def fe(self, path):
        if path == "/fe-healthz":
            self.reply(200, f"ok {NAME}")
        elif path == "/config.json":
            self.reply(200, f'{{"env":"{APP_ENV}"}}', "application/json")
        elif path in ("/sw.js", "/manifest.webmanifest") or path.startswith("/icons/"):
            self.reply(200, f"public {path}", "application/octet-stream", [("Cache-Control", "public, max-age=0")])
        elif path == "/_next/static/chunks/fe-only.js":
            # 풀에 없는 자산은 FE가 대신 응답한다
            self.reply(200, f"fe-only {NAME}", "text/javascript", [("Cache-Control", "public, max-age=31536000, immutable")])
        elif path.startswith("/_next/static/"):
            self.reply(404, "not found")
        elif path == "/echo":
            self.reply(200, self.echo())
        elif path == "/ssr-probe":
            # 서버 쪽 호출: BE_INTERNAL_URL(Caddy 내부 리스너)을 거쳐 활성 색 BE의 색을 읽는다
            with urllib.request.urlopen(BE_INTERNAL_URL + "/api/v1/version", timeout=5) as r:
                self.reply(200, f"be={r.headers.get('X-App-Version')}")
        elif path == "/stream":
            self.stream()
        else:
            self.reply(
                200,
                PAGE.format(name=NAME, env=APP_ENV),
                "text/html; charset=utf-8",
                [("Cache-Control", "private, no-cache, no-store, max-age=0, must-revalidate")],
            )

    def stream(self):
        # 첫 덩어리를 보낸 뒤 1.5초 있다가 나머지를 보낸다. Caddy가 모아서 한 번에 내보내면 첫 바이트가 늦다
        self.send_response(200)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.send_header("Transfer-Encoding", "chunked")
        self.end_headers()

        def chunk(data):
            self.wfile.write(b"%x\r\n" % len(data) + data + b"\r\n")
            self.wfile.flush()

        chunk(b"<!-- first -->" + b"x" * 4096)
        time.sleep(1.5)
        chunk(b"<!-- last -->")
        self.wfile.write(b"0\r\n\r\n")

    def log_message(self, fmt, *args):
        pass


ThreadingHTTPServer(("", PORT), Handler).serve_forever()
````

````python
"""스트리밍 응답의 첫 본문 바이트와 마지막 바이트가 도착한 시간을 잰다(infra/edge/test).

import sys
import time

ctx.verify_mode = ssl.CERT_NONE

raw = socket.create_connection(("127.0.0.1", port), timeout=30)
conn = ctx.wrap_socket(raw, server_hostname=host)
conn.sendall(f"GET {path} HTTP/1.1\r\nHost: {host}\r\nAccept-Encoding: gzip\r\nConnection: close\r\n\r\n".encode())

buf = b""
first = None
while True:
    data = conn.recv(65536)
    if not data:
        break
    buf += data
    if first is None and b"\r\n\r\n" in buf and len(buf.split(b"\r\n\r\n", 1)[1]) > 0:
        first = time.monotonic() - start
total = time.monotonic() - start
print(f"first={first if first is not None else total:.2f} total={total:.2f}")
````

````bash
garage() { dcl exec -T -e RUST_LOG=warn garage /garage -c /etc/garage/garage.toml "$@"; }
edgectl() { bash infra/edge/edgectl.sh "$@"; }

up() {
  bash infra/local/fit-local.sh up
  # fit-local.sh는 dev 버킷만 만든다. prod 버킷도 같은 키로 쓸 수 있게 만든다
  # shellcheck source=/dev/null
  . infra/local/local.env.example
  garage bucket info fit-prod-photos >/dev/null 2>&1 || garage bucket create fit-prod-photos >/dev/null

}

FAILED=0
pass() { printf 'PASS  %s\n' "$1"; }
fail() { printf 'FAIL  %s\n' "$1"; FAILED=$((FAILED + 1)); }
ok_if() { if [ "$2" = "1" ]; then pass "$1"; else fail "$1"; fi; }
is() { if [ "$1" = "$2" ]; then echo 1; else echo 0; fi; }
has() { case "$1" in *"$2"*) echo 1 ;; *) echo 0 ;; esac; }
lower() { printf '%s' "$1" | tr '[:upper:]' '[:lower:]'; }
PROD="https://$PROD_HOST:$HTTPS_PORT"
DEV="https://$DEV_HOST:$HTTPS_PORT"
RESOLVE=(--resolve "$PROD_HOST:$HTTPS_PORT:127.0.0.1" --resolve "$DEV_HOST:$HTTPS_PORT:127.0.0.1")
# 게이트 쿠키는 -b로 보낸다. curl의 --aws-sigv4는 -H로 준 헤더를 서명 대상에 넣어서, Caddy가 지운 Cookie 헤더와 서명이 어긋난다.
# 실제 클라이언트(브라우저의 presigned URL)는 Cookie를 서명하지 않는다
GATE=(-b "fit_dev=$KEY")
# Docker Desktop(Windows)의 포트 포워더는 새 연결을 간헐적으로 거부한다(200건에 1건 정도이고 Caddy 쪽 원인이 아니다).
# curl 자체의 --retry는 이 오류를 재시도하지 않아서, 연결 실패(종료 코드 7)만 다시 시도하는 래퍼를 쓴다.
# 재시도가 결과를 가리는 점검(reload 중 응답, 게시되지 않은 포트)은 재시도 없는 curl_once를 쓴다.
curl_once() { curl -sSk --max-time 60 "${RESOLVE[@]}" "$@"; }
curl_retry() {
  local rc=0
  for _ in 1 2 3; do
    curl_once "$@" 2>/dev/null && return 0
    rc=$?
    [ "$rc" = 7 ] || return "$rc"
    sleep 0.5
  done
  curl_once "$@"
}
# 상태 코드는 -w로 마지막 줄에 받는다(curl의 -o /dev/null은 Git Bash의 Windows용 curl에서 쓰기 오류가 난다)
http_code_once() { curl_once "$@" -w '\n%{http_code}' | tail -n 1; }
http_code() { curl_retry "$@" -w '\n%{http_code}' | tail -n 1; }
resp() { curl_retry -i "$@" | tr -d '\r'; }
body() { resp "$@" | awk 'f { print } /^$/ && !f { f = 1 }'; }
s3sign() { curl_retry --aws-sigv4 "aws:amz:garage:s3" --user "$S3_ACCESS_KEY:$S3_SECRET_KEY" "$@"; }

check_proxy_headers_and_cookies() {
  local out
  for path in /api/echo /echo; do
    out="$(resp "$PROD$path" -H "X-Forwarded-For: 6.6.6.6")"
    ok_if "프록시($path): 외부에서 온 X-Forwarded-For는 무시한다" "$(is "$(has "$out" "xff=6.6.6.6")" 0)"
    ok_if "프록시($path): X-Forwarded-Proto는 https다" "$(has "$out" "proto=https")"
    ok_if "프록시($path): Host는 원본(포트 포함)을 유지한다" "$(has "$out" "host=$PROD_HOST:$HTTPS_PORT")"
  done
  out="$(resp "$PROD/echo" -H "Cookie: fit_prod_session=xyz; other=1")"
  ok_if "prod: 쿠키는 그대로 FE로 전달한다" "$(is "$(has "$out" "fit_prod_session=xyz")$(has "$out" "other=1")" 11)"
  for path in /api/echo /echo; do
    out="$(resp "$DEV$path" -H "Cookie: fit_dev=$KEY; other=1")"
    ok_if "dev($path): 게이트 쿠키는 통과하고 다른 쿠키는 전달한다" "$(is "$(has "$out" "other=1")$(has "$out" "name=dev")" 11)"
    ok_if "dev($path): 게이트 키는 앱 컨테이너로 보내지 않는다" "$(is "$(has "$out" "fit_dev")$(has "$out" "$KEY")" 00)"
  done
  out="$(resp "$PROD/")"
  ok_if "FE 응답의 Cache-Control은 Caddy가 바꾸지 않는다" "$(has "$(lower "$out")" "cache-control: private, no-cache, no-store, max-age=0, must-revalidate")"
  ok_if "Server·X-Powered-By 헤더는 upstream이 보내도 지운다" "$(is "$(has "$(lower "$out")" "server:")$(has "$(lower "$out")" "x-powered-by:")" 00)"
}

check_body_limits() {
  local code
  head -c 1000000 /dev/zero > .tmp-edge-1mb.bin
  head -c 3000000 /dev/zero > .tmp-edge-3mb.bin
  head -c 11000000 /dev/zero > .tmp-edge-11mb.bin
  # 목 BE는 본문을 끝까지 읽는다. 본문을 읽지 않는 upstream은 한도를 넘기 전에 응답을 먼저 돌려줘 한도가 드러나지 않는다
  code="$(http_code -X POST --data-binary @.tmp-edge-3mb.bin "$PROD/api/upload")"
  ok_if "본문 한도: /api 는 2MB 초과를 413으로 거부" "$(is "$code" 413)"
  code="$(http_code -X POST --data-binary @.tmp-edge-1mb.bin "$PROD/api/upload")"
  ok_if "본문 한도: /api 는 2MB 이하(1MB)를 통과" "$(is "$code" 200)"
  code="$(s3sign -X PUT --data-binary @.tmp-edge-11mb.bin "${GATE[@]}" -w '\n%{http_code}' "$DEV/fit-dev-photos/confirmed/too-big.bin" | tail -n 1)"
  ok_if "본문 한도: 사진 경로는 10MB 초과를 413으로 거부" "$(is "$code" 413)"
  rm -f .tmp-edge-1mb.bin .tmp-edge-3mb.bin .tmp-edge-11mb.bin
}

check_photos() {
  local obj="confirmed/edge-test.txt" out
  for env in prod dev; do
    local base="$PROD" extra=()
    if [ "$env" = "dev" ]; then base="$DEV"; extra=("${GATE[@]}"); fi
    ok_if "사진($env): 서명한 S3 PUT이 엣지를 거쳐 통과한다(Host 보존)" \
      "$(is "$(s3sign -X PUT --data-binary "photo-$env" ${extra[@]+"${extra[@]}"} -w '\n%{http_code}' "$base/fit-$env-photos/$obj" | tail -n 1)" 200)"
    ok_if "사진($env): 서명 없는 S3 GET은 403이다" "$(is "$(http_code ${extra[@]+"${extra[@]}"} "$base/fit-$env-photos/$obj")" 403)"
    out="$(resp ${extra[@]+"${extra[@]}"} "$base/photos/$env/confirmed/edge-test.txt")"
    ok_if "사진($env): 웹 엔드포인트로 공개 읽기(200, 본문 일치)" "$(is "$(has "$out" "HTTP/")$(has "$out" "photo-$env")" 11)"
    ok_if "사진($env): 읽기 응답은 Cache-Control: public" "$(has "$(lower "$out")" "cache-control: public, max-age=86400")"
    ok_if "사진($env): pending/은 공개하지 않는다" "$(is "$(http_code ${extra[@]+"${extra[@]}"} "$base/photos/$env/pending/edge-test.txt")" 404)"
    ok_if "사진($env): 서명한 S3 DELETE" \
      "$(is "$(s3sign -X DELETE ${extra[@]+"${extra[@]}"} -w '\n%{http_code}' "$base/fit-$env-photos/$obj" | tail -n 1)" 204)"
  done
  # 호스트마다 자기 환경의 버킷 경로만 프록시한다. 다른 환경의 경로는 FE가 받는다(실제 FE는 404를 낸다)
  ok_if "사진: dev 호스트는 prod 버킷 경로를 garage로 보내지 않는다" "$(has "$(body "${GATE[@]}" "$DEV/fit-prod-photos/confirmed/edge-test.txt")" "mock-fe dev")"
  ok_if "사진: prod 호스트는 dev 버킷 경로를 garage로 보내지 않는다" "$(has "$(body "$PROD/fit-dev-photos/confirmed/edge-test.txt")" "mock-fe blue")"
}

check_static_pool() {
  local out
  out="$(resp "$PROD/_next/static/chunks/old-9f8e7d6c.js")"
  ok_if "풀: 현재 릴리스에 없는 이전 해시 자산을 풀에서 준다(200, immutable)" \
    "$(is "$(has "$out" "pool-old prod")$(has "$(lower "$out")" "cache-control: public, max-age=31536000, immutable")" 11)"
  ok_if "풀: 풀에 있는 자산은 FE를 거치지 않고 Caddy가 준다" "$(has "$(body "$PROD/_next/static/chunks/app-1a2b3c4d.js")" "pool-app prod")"
  ok_if "풀: 풀에 없는 자산은 FE가 대신 응답한다" "$(has "$(body "$PROD/_next/static/chunks/fe-only.js")" "fe-only blue")"
  ok_if "풀: 어디에도 없는 자산은 404다" "$(is "$(http_code "$PROD/_next/static/chunks/nope.js")" 404)"
  ok_if "풀: dev 풀은 prod 풀과 분리돼 있다" "$(has "$(body "${GATE[@]}" "$DEV/_next/static/chunks/old-9f8e7d6c.js")" "pool-old dev")"
  out="$(body --path-as-is "$PROD/_next/static/../../../../etc/passwd")"
  ok_if "풀: 상위 경로(..)로 풀 밖의 파일을 읽을 수 없다" "$(is "$(has "$out" "root:")" 0)"
}

check_streaming() {
  local out first total
  out="$("$PY" infra/edge/test/probe.py "$HTTPS_PORT" "$PROD_HOST" /stream)"
  first="$(printf '%s' "$out" | sed -E 's/.*first=([0-9.]+).*/\1/')"
  total="$(printf '%s' "$out" | sed -E 's/.*total=([0-9.]+).*/\1/')"
  ok_if "스트리밍: 첫 덩어리가 마지막 덩어리(1.5초 뒤)를 기다리지 않고 도착한다(first=$first total=$total)" \
    "$(awk -v f="$first" -v t="$total" 'BEGIN { print (f < 1.0 && t >= 1.4) ? 1 : 0 }')"
}

# set_state 환경 서비스 호스트 포트: 상태 파일을 임시 이름으로 쓴 뒤 mv로 바꾼다(배포 스크립트가 할 일)
set_state() {
  docker run --rm -v "${EDGE_PROJECT}_state:/srv/fit/state" "$CADDY_IMAGE" sh -c \
    "printf 'reverse_proxy $3:$4 {\n\tlb_try_duration 5s\n\tlb_try_interval 250ms\n}\n' > /srv/fit/state/upstream-$1-$2.caddy.new && mv /srv/fit/state/upstream-$1-$2.caddy.new /srv/fit/state/upstream-$1-$2.caddy"
}
active_be() { resp "$PROD/api/v1/version" | tr '[:upper:]' '[:lower:]' | awk -F': ' '$1 == "x-app-version" { print $2 }'; }
active_fe() { body "$PROD/" | sed -nE 's/.*mock-fe ([a-z]+) prod.*/\1/p'; }
ssr_be() { body "$PROD/ssr-probe" | sed -nE 's/^be=(.*)$/\1/p'; }

check_blue_green() {
  local failures server_errors out
  ok_if "전환: 처음 활성 색은 BE blue, FE blue다" "$(is "$(active_be)$(active_fe)" blueblue)"
  ok_if "전환: FE 서버가 내부 리스너로 읽은 BE도 blue다" "$(is "$(ssr_be)" blue)"
  out="$(edgectl status)"
  ok_if "edgectl status: 활성 색 네 줄을 보여 준다" \
    "$(is "$(has "$out" "prod  be  be-prod-blue:8080")$(has "$out" "prod  fe  fe-prod-blue:3000")$(has "$out" "dev   be  be-dev:8080")$(has "$out" "dev   fe  fe-dev:3000")" 1111)"
  set_state prod be be-prod-green 8080
  set_state prod fe fe-prod-green 3000
  ok_if "전환: 상태 파일만 바꾸고 reload하기 전에는 그대로다" "$(is "$(active_be)$(active_fe)" blueblue)"
  # reload하는 동안 요청이 계속 성공해야 한다. 호스트 경로(포트 포워더)와 compose 망 안쪽 경로를 함께 본다
  (for _ in $(seq 1 40); do http_code_once "$PROD/"; sleep 0.1; done) > .tmp-edge-reload.log &
  local bg=$!
  dc exec -T fe-prod-blue python /mock/inner.py http://caddy:8081/api/v1/version 150 > .tmp-edge-inner.log &
  local bg2=$!
  sleep 0.5
  out="$(edgectl reload 2>&1 || true)"
  wait "$bg" "$bg2" || true
  server_errors="$(grep -cE '^(4|5)[0-9][0-9]$' .tmp-edge-reload.log || true)"
  failures="$(tr -d '\r\n' < .tmp-edge-inner.log)"
  rm -f .tmp-edge-reload.log .tmp-edge-inner.log
  ok_if "edgectl reload: 성공 메시지를 낸다" "$(has "$out" "OK reload 완료")"
  ok_if "전환: reload 후 활성 색은 BE green, FE green이다" "$(is "$(active_be)$(active_fe)" greengreen)"
  ok_if "전환: FE는 재시작 없이 BE의 새 색을 본다(내부 리스너 한 곳이 색을 고른다)" "$(is "$(ssr_be)" green)"
  ok_if "전환: reload 중 호스트 경로에서 4xx·5xx 응답이 없다(발견 ${server_errors}건)" "$(is "$server_errors" 0)"
  ok_if "전환: reload 중 compose 망 안의 요청 150건이 모두 성공한다(실패 ${failures}건)" "$(is "$failures" 0)"
  # BE와 FE는 따로 전환된다
  set_state prod be be-prod-blue 8080
  edgectl reload >/dev/null
  ok_if "전환: BE만 blue로 되돌리면 FE는 green 그대로이고 FE가 보는 BE는 blue다" "$(is "$(active_be)$(active_fe)$(ssr_be)" bluegreenblue)"
  # 문법이 틀린 상태 파일은 check와 reload가 거부하고 현재 설정이 유지된다
  docker run --rm -v "${EDGE_PROJECT}_state:/srv/fit/state" "$CADDY_IMAGE" sh -c "printf 'reverse_proxy be-prod-green:8080 {\n' > /srv/fit/state/upstream-prod-be.caddy"
  if edgectl check >/dev/null 2>&1; then fail "안전: 문법이 틀린 상태 파일을 check가 통과시켰다"; else pass "안전: 문법이 틀린 상태 파일은 edgectl check가 거부한다"; fi
  if edgectl reload >/dev/null 2>&1; then fail "안전: 문법이 틀린 상태 파일을 reload가 받아들였다"; else pass "안전: 문법이 틀린 상태 파일은 edgectl reload가 거부한다"; fi
  ok_if "안전: reload가 거부된 뒤에도 서비스는 직전 설정(BE blue)으로 계속 응답한다" "$(is "$(active_be)" blue)"
  set_state prod be be-prod-blue 8080
  # 문법은 맞지만 없는 호스트를 가리키는 upstream은 check와 reload를 통과한다. 그래서 reload 뒤 스모크가 필요하다
  set_state prod be be-prod-nowhere 8080
  edgectl reload >/dev/null || true
  ok_if "스모크 필요: 없는 upstream은 reload를 통과하고 요청은 502다" "$(is "$(http_code "$PROD/healthz")" 502)"
  set_state prod be be-prod-blue 8080
  set_state prod fe fe-prod-blue 3000
  edgectl reload >/dev/null
  ok_if "전환: 모두 blue로 되돌렸다" "$(is "$(active_be)$(active_fe)" blueblue)"
}

check_internal_and_logs() {
  local logs
  ok_if "내부 리스너: dev의 FE 서버는 dev BE를 본다" "$(is "$(body "${GATE[@]}" "$DEV/ssr-probe" | sed -nE 's/^be=(.*)$/\1/p')" dev)"
  ok_if "내부 리스너: 호스트에는 게시되지 않는다(8081, 8082)" \
    "$(is "$(http_code_once --max-time 3 http://127.0.0.1:8081/healthz 2>/dev/null || true)$(http_code_once --max-time 3 http://127.0.0.1:8082/healthz 2>/dev/null || true)" 000000)"
  http_code "$DEV/?k=$KEY" >/dev/null
  http_code "${GATE[@]}" "$DEV/" >/dev/null
  logs="$(dc logs caddy 2>&1)"
  ok_if "로그: dev 키(쿼리 k와 쿠키)가 로그에 남지 않는다" "$(is "$(has "$logs" "$KEY")" 0)"
  ok_if "로그: 접근 로그는 JSON이다" "$(has "$logs" '"request":{')"
  ok_if "메트릭: compose 망 안에서 caddy:9180/metrics 가 응답한다" \
    "$(has "$(dc exec -T be-dev python -c "import urllib.request; print(urllib.request.urlopen('http://caddy:9180/metrics').read(200000).decode())" 2>/dev/null)" "caddy_http_requests_total")"
  ok_if "메트릭: 호스트에는 게시되지 않는다" "$(is "$(http_code_once --max-time 3 http://127.0.0.1:9180/metrics 2>/dev/null || true)" 000)"
  ok_if "관리 API(2019)는 호스트에 게시되지 않는다" "$(is "$(http_code_once --max-time 3 http://127.0.0.1:2019/config/ 2>/dev/null || true)" 000)"
  ok_if "http→https 리다이렉트는 엣지의 80이 한다" "$(has "301 302 307 308" "$(http_code "http://$PROD_HOST:$HTTP_PORT/")")"
}

verify() {
  # shellcheck source=/dev/null
  . infra/local/local.env.example
  FAILED=0
  bash infra/edge/verify-edge.sh --prod "$PROD" --dev "$DEV" --dev-key "$KEY" --http "http://$PROD_HOST:$HTTP_PORT" \
    --resolve "$PROD_HOST:$HTTPS_PORT:127.0.0.1" --resolve "$DEV_HOST:$HTTPS_PORT:127.0.0.1" --retry 3 --insecure || FAILED=$((FAILED + 1))
  echo "--- 엣지 동작 시험"
  check_proxy_headers_and_cookies
  check_body_limits
  check_photos
  check_static_pool
  check_streaming
  check_blue_green
  check_internal_and_logs
  if [ "$FAILED" -gt 0 ]; then
    printf '\n%d개 점검 실패\n' "$FAILED"
    return 1
  fi
  printf '\n엣지 시험 통과\n'
}

down() {
  dc down -v
  bash infra/local/fit-local.sh reset
}

esac
````

- dev 게이트: 통과한 요청에서 게이트 쿠키는 앱 컨테이너로 가지 않고 다른 쿠키는 전달
- 본문 한도: `/api` 2MB 초과 413, 1MB 통과, 사진 경로 10MB 초과 413
- 사진(prod, dev 각각): 서명한 PUT 통과, 서명 없는 GET 403, 웹 엔드포인트 공개 읽기, `Cache-Control: public`, `pending/` 404, 서명한 DELETE. 호스트마다 다른 환경의 버킷 경로는 garage로 가지 않는다
- 정적 자산 풀: 이전 해시 자산(200, `immutable`), 풀에 있으면 FE를 거치지 않음, 풀에 없으면 FE가 응답, 어디에도 없으면 404, dev와 prod 풀 분리, `..` 경로로 풀 밖을 읽을 수 없음
- SSR 스트리밍: `encode`가 켜진 상태에서 첫 덩어리가 1.5초 뒤의 마지막 덩어리를 기다리지 않고 도착
- 전환: BE와 FE를 green으로 바꿔도 reload 전에는 그대로, `edgectl.sh reload` 뒤 green, FE 서버가 읽는 BE 색도 재시작 없이 green, reload 중 4xx·5xx 없음과 망 안 요청 150건 성공, BE만 blue로 되돌리면 FE는 green 그대로, 문법이 틀린 상태 파일은 `check`와 `reload`가 거부하고 서비스는 직전 설정으로 응답, 없는 upstream은 502, 모두 blue로 복귀
- 내부 리스너: dev의 FE 서버는 dev BE를 본다, 8081·8082는 호스트에 게시되지 않음
- 로그에 dev 키가 없고 JSON, 메트릭은 망 안에서만, 관리 API 미게시, 80 포트 리다이렉트

````bash
#!/bin/sh
# 엣지 Caddy 설정의 형식(caddy fmt)과 문법(caddy validate)을 검사한다(설계 5절).
# caddy 이미지 안에서 저장소 루트를 작업 디렉터리로 돈다(CI의 lint:caddy, 로컬 러너).
# validate에는 환경변수와 상태 파일(upstream-*.caddy)이 필요해서 예제 env와 형식 견본을 쓴다.
# 인증서 단계(staging, production)와 HSTS(off, on)의 네 조합을 모두 확인한다.
set -eu

CONF=infra/edge/conf
bad=0

for f in "$CONF/Caddyfile" "$CONF"/acme/*.caddy "$CONF"/hsts/*.caddy infra/edge/state-sample/*.caddy; do
  if ! caddy fmt --diff "$f" >/dev/null 2>&1; then
    echo "FAIL caddy fmt 필요: $f (caddy fmt --overwrite $f)"
    bad=1
  fi
done

mkdir -p /srv/fit/state
cp infra/edge/state-sample/*.caddy /srv/fit/state/
set -a
# shellcheck source=/dev/null
. infra/edge/edge.env.example
set +a
for mode in staging production; do
  for hsts in off on; do
    if ! ACME_MODE="$mode" HSTS_MODE="$hsts" caddy validate --config "$CONF/Caddyfile" --adapter caddyfile >/dev/null 2>&1; then
      echo "FAIL caddy validate: ACME_MODE=$mode HSTS_MODE=$hsts"
      bad=1
    fi
  done
done

if [ "$bad" = 0 ]; then
  echo "OK caddy (fmt, validate)"
fi
exit "$bad"
````

````markdown
# 엣지 (Caddy)

서버 A의 `fit-edge` 프로젝트다. 80·443만 게시하고 prod와 dev는 호스트(`PROD_HOST`, `DEV_HOST`)로 나눈다. 뒤에는 Next.js(SSR) FE와 BE가 있다. 설계는 [design.md](../../docs/infra/design.md) 5절이다.

## 자주 하는 일

| 하고 싶은 일 | 명령 |
|---|---|
| 지금 상태와 활성 색 보기 | `bash infra/edge/edgectl.sh status` |
| 설정 문법만 검사 | `bash infra/edge/edgectl.sh check` |
| 설정이나 상태 파일을 적용(무중단) | `bash infra/edge/edgectl.sh reload`, 이어서 `verify-edge.sh` |
| 엣지가 정상인지 점검 | `bash infra/edge/verify-edge.sh --prod https://<PROD_HOST> --dev https://<DEV_HOST> --dev-key <키> --http http://<PROD_HOST>` |
| DNS를 바꾸기 전에 서버만 점검 | 위 명령에 `--resolve <호스트>:443:<서버 IP>`를 호스트마다 더한다 |
| 노트북에서 엣지 전체를 시험 | `bash infra/edge/test/test-edge.sh up`, `verify`, `down` |

`edgectl.sh`는 `/etc/fit/edge.env`를 읽는다(`FIT_EDGE_ENV`로 바꿀 수 있다). 배포 스크립트도 같은 `reload`를 부른다.

## 요청 흐름

```
브라우저 ─443→ caddy ┬ /_next/static/*                ─→ 풀(pool)에 있으면 Caddy가 직접, 없으면 FE
                     ├ /api/*, /healthz               ─→ BE(활성 색)
                     ├ /fit-<환경>-photos/*           ─→ garage S3 API(업로드)
                     ├ /photos/<환경>/confirmed/*     ─→ garage 웹 엔드포인트(읽기)
                     └ 그 외 전부                     ─→ FE(활성 색, Next.js SSR)
FE 서버 ─ caddy:8081(prod), caddy:8082(dev) ─→ BE(활성 색)
```

FE 서버가 BE를 부를 때는 Caddy의 내부 리스너를 거친다(`BE_INTERNAL_URL`). 활성 색을 고르는 곳이 상태 파일 한 곳이라 FE는 BE의 색을 모른다. 내부 리스너는 호스트에 게시하지 않는다. 같은 망의 컨테이너는 포트만 맞으면 어느 환경의 리스너에도 닿으므로 `BE_INTERNAL_URL`의 포트가 환경과 맞는지는 배포 사전 점검이 확인한다(계획 1C-2).

## 서버가 갖출 것

- DNS: `PROD_HOST`와 `DEV_HOST`의 A 레코드가 서버 A의 공인 IP를 가리켜야 인증서가 발급된다.
- 망 `net-edge`, `net-prod`, `net-dev`, `net-obs`를 먼저 만든다(계획 1F). 이름은 `FIT_NET_*`로 바꿀 수 있다.
- 정적 자산 풀 `/srv/fit/web/<환경>/pool/`. 안에 `_next/static/…`가 URL 경로 그대로 쌓인다. 쌓는 일과 정리는 배포 스크립트가 한다(계획 1C-2).
- 상태 디렉터리 `/srv/fit/state/`에 `upstream-prod-be.caddy`, `upstream-prod-fe.caddy`, `upstream-dev-be.caddy`, `upstream-dev-fe.caddy`. 형식은 `state-sample/`과 같다.
- 인증서 보관 볼륨 `caddy_data`는 지우지 않고 백업한다(재발급 한도).

## 상태 파일을 바꿀 때

임시 이름으로 쓴 뒤 `mv`로 바꾸고 `edgectl.sh reload`를 부른다(`check`를 통과해야 reload한다).

- 문법이 틀린 파일은 `check`와 `reload`가 거부하고 직전 설정이 유지된다.
- 문법은 맞지만 없는 호스트를 가리키면 `reload`를 통과하고 요청이 502가 된다. reload 뒤에는 반드시 Caddy 경유 점검(`verify-edge.sh`)으로 확인한다.

## 인증서 단계

1. 첫날: `ACME_MODE=staging`, `HSTS_MODE=off`로 시작해 발급 경로(80 도달, DNS)를 확인한다.
2. 이어서 `ACME_MODE=production`으로 바꿔 운영 인증서를 받는다. 이때부터 기본 이슈어 둘(Let's Encrypt, ZeroSSL)을 쓴다.
3. 운영 인증서가 확정되면 `HSTS_MODE=on`으로 바꾼다.
````
