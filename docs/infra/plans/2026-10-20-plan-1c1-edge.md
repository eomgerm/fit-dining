# 엣지(Caddy) 구현 계획 (Plan 1C-1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버 A의 엣지(Caddy)를 만든다. PWA 정적 서빙(SPA 폴백, 캐시 헤더, 해시 자산 누적 풀), `/api`·`/healthz` 프록시와 활성 색 전환 구조, dev 쿠키 게이트, 사진 업로드·읽기 프록시, 인증서 단계 전환, 로그·메트릭을 설정으로 정의하고, 서버 없이 노트북에서 실제로 띄워 시험하는 환경과 점검 스크립트를 함께 만든다.

**Architecture:** `infra/edge/conf/Caddyfile` 하나가 prod(443)와 dev(8443) 사이트를 정의하고, 환경별 라우팅과 PWA 서빙은 `{args[0]}`을 받는 스니펫으로 공유한다. 인증서 단계(`ACME_MODE`)와 HSTS(`HSTS_MODE`)는 환경변수가 고르는 조각 파일로 바꾼다. 활성 색은 배포 스크립트가 쓰는 `/srv/fit/state/upstream-<환경>.caddy`를 import해서 정한다. 노트북 시험 환경(`infra/edge/test/`)은 목 BE, 시험용 웹 트리, 1B 로컬 스택의 실제 garage를 붙인다.

**Tech Stack:** Caddy 2.11.7, Docker Compose v2(2.24 이상, `!override` 사용), bash, curl 7.75 이상, python 3.12(목 BE 한 개).

**Spec:** [docs/infra/design.md](../design.md) (5절 엣지·TLS, 6.8절 PWA, 12.5절 프런트 계약, 13.2절 시크릿)

## 검증 결과

이 계획의 코드는 저장소를 clone한 임시 복사본(저장소 밖)에서 실행해 확인했다.

- 러너는 모든 단계가 통과하고(be의 Dockerfile이 없어 건너뛰는 한 단계 제외) 자가 테스트 10종이 통과한다. `lint:caddy`의 스크립트 줄을 핀한 이미지(`caddy:2.11.7`)에서 실행해도 통과한다.
- 노트북 시험 환경(`test-edge.sh`)은 빈 상태에서 켜서 `verify-edge.sh`와 동작 시험이 모두 통과한다. 같은 `verify`를 다시 돌려도 통과하고, 잘못된 dev 키나 닿지 않는 주소를 주면 실패한다.
- 인증서 단계: `ACME_MODE=staging`은 staging 이슈어 하나만, `production`은 Let's Encrypt와 ZeroSSL 둘을 가진 설정이 된다(`caddy adapt` 결과). 그래서 운영 단계에서 `acme_ca`를 지정하지 않는다.
- 사진 경로: 헤더 서명(SigV4) PUT이 엣지를 거쳐 로컬 garage에서 통과한다(Host 보존). 서명 없는 GET은 403, 웹 엔드포인트의 `confirmed/`는 공개 읽기(200, `Cache-Control: public`), `pending/`은 404, 10MB 초과 업로드는 413이다.
- 본문 한도: 2MB 초과 `/api` 요청은 413이다. 본문을 읽지 않는 upstream은 한도를 넘기 전에 응답을 먼저 돌려줘서 한도가 드러나지 않으므로, 시험은 본문을 끝까지 읽는 목 BE를 쓴다.
- 쿠키: prod는 `fit_dev`를, dev는 `fit_prod_` 접두사 쿠키를 BE로 보내지 않고 나머지 쿠키는 그대로 전달한다. 로그에는 쿼리의 `k`도 쿠키의 키도 남지 않는다.
- 누적 풀: 현재 릴리스에 없는 이전 해시 자산을 풀에서 준다(200, `immutable`). 없는 자산은 404이고 `immutable`이 붙지 않는다.
- 전환: 상태 파일만 바꾸면 트래픽은 그대로고 `reload` 뒤에 옮겨진다. reload 중 compose 망 안의 요청 150건이 모두 성공한다. 문법이 틀린 상태 파일은 `validate`와 `reload`가 거부하고 직전 설정이 유지된다. 문법은 맞지만 없는 호스트를 가리키는 upstream은 둘 다 통과해서 요청이 502가 된다. 그래서 reload 뒤 스모크가 필요하다(계획 1C-2).
- 메트릭 `:9180/metrics`는 compose 망 안에서 응답하고 호스트에는 게시되지 않는다. 관리 API(2019)도 호스트에 게시되지 않는다.
- Caddy의 `servers` 안 `metrics` 옵션은 폐기 예정이라 전역 `metrics`를 쓴다.
- `curl -o /dev/null`은 Git Bash의 Windows용 curl에서 쓰기 오류가 나서 스크립트는 상태 코드를 `-w`로 받는다. Docker Desktop의 포트 포워더는 reload 중 호스트 경로 요청을 드물게(수백 건에 한 건) 거부했다. 같은 시간 compose 망 안의 요청은 1,200건 중 실패가 없었다.

아래 코드를 그대로 옮기면 같은 결과가 나와야 한다. 다르면 코드를 고치기 전에 원인을 먼저 확인한다.

**아직 확인하지 못한 것**

- 실제 ACME 발급(staging, production)과 `HSTS_MODE=on` 이후의 동작. 서버에서 80 도달과 DNS가 필요하다(M1).
- 실제 BE(Spring)와의 연동. 프록시 헤더 처리(`server.forward-headers-strategy`)와 `/healthz`는 목 BE로만 확인했다.
- 실제 PWA 번들(Next.js 정적 export) 서빙. 해시 자산을 파일명의 16진수 8자 이상 덩어리로 알아본다는 가정이고, 프런트의 실제 파일명 규칙은 합의 전이다(12.5절 #5).
- presigned URL과 POST policy 업로드, garage 수명주기(설계 7.4절의 서버 스파이크).
- Linux 서버의 포트 게시와 ufw, Mac·Linux에서의 시험 환경 실행, 메모리 한도 150m의 실측.

## Global Constraints

1A·1B의 전역 제약이 모두 적용된다([plan 1A](2026-10-15-plan-1a-foundation-guardrails.md), [plan 1B](2026-10-19-plan-1b-local-env-contracts.md)). 이 계획에서 더 지키는 것은 다음과 같다.

- 호스트에 게시하는 포트는 caddy의 80·443·8443뿐이다. 시험 환경은 `127.0.0.1`의 18080·18443·18444만 쓴다.
- Caddy 파일(`Caddyfile`, `*.caddy`)은 탭으로 들여쓰고 `caddy fmt`가 바꾸지 않는 형태여야 한다.

- 시험용 값(`DEV_GATE_KEY` 등)은 엔트로피가 낮은 값이라 시크릿 검사에 걸리지 않는다. 서버 값으로 쓰지 않는다.
- 검증용 시험 환경은 `fit-edge-test`, `fit-edge-test-local` 프로젝트로 띄우고 `down`으로 지운다(이름 패턴 일괄 삭제 금지).
- 커밋 메시지와 브랜치는 1B와 같은 규칙이다. 브랜치는 `infra/feat/edge-caddy-S15P31A302-19`다.

- dev 게이트는 쿠키 값이 `DEV_GATE_KEY`와 같을 때만 연다. `/?k=<키>`가 쿠키를 발급하고 `/`로 보낸다. 키는 영문자·숫자·`_`·`-`만 쓴다(쿠키와 정규식에 안전해야 한다).

FAILED=0
pass() { printf 'PASS  %s\n' "$1"; }
fail() { printf 'FAIL  %s\n' "$1"; FAILED=$((FAILED + 1)); }
skip() { printf 'SKIP  %s\n' "$1"; }

# fetch URL [curl 인자...]: STATUS, HEADERS(소문자), BODY를 채운다. 리다이렉트는 따라가지 않는다.
STATUS="" HEADERS="" BODY=""
fetch() {
  local raw
  raw="$("${CURL[@]}" -i "$@" | tr -d '\r')" || { STATUS="000"; HEADERS=""; BODY=""; return; }
  STATUS="$(printf '%s\n' "$raw" | head -n 1 | awk '{print $2}')"
  HEADERS="$(printf '%s\n' "$raw" | awk 'NR > 1 { if ($0 == "") exit; print }' | tr '[:upper:]' '[:lower:]')"
  BODY="$(printf '%s\n' "$raw" | awk 'f { print } /^$/ && !f { f = 1 }')"
}
header_value() { printf '%s\n' "$HEADERS" | awk -F': ' -v k="$1" 'tolower($1) == k { sub(/^[^:]*: /, ""); print; exit }'; }
expect() { # expect NAME 조건(참이면 통과)
  if [ "$2" = "1" ]; then pass "$1"; else fail "$1 (status=$STATUS)"; fi
}
is() { if [ "$1" = "$2" ]; then echo 1; else echo 0; fi; }
has() { case "$1" in *"$2"*) echo 1 ;; *) echo 0 ;; esac; }

check_site() { # check_site 라벨 URL [curl 인자...]
  local label="$1" base="$2" asset
  shift 2
  fetch "$base/" "$@"
  expect "$label: / 는 200" "$(is "$STATUS" 200)"
  expect "$label: index.html은 no-cache" "$(has "$(header_value cache-control)" no-cache)"
  expect "$label: nosniff 헤더" "$(is "$(header_value x-content-type-options)" nosniff)"
  expect "$label: Server 헤더 없음" "$(is "$(header_value server)" "")"
  expect "$label: h3(Alt-Svc) 광고 없음" "$(is "$(header_value alt-svc)" "")"
  asset="$(printf '%s\n' "$BODY" | grep -oE '/[A-Za-z0-9_./-]*[./-][0-9a-f]{8,}\.js' | head -n 1)"
  for f in /sw.js /manifest.webmanifest /config.json; do
    fetch "$base$f" "$@"
    expect "$label: $f 는 200 + no-cache" "$(is "$STATUS$(has "$(header_value cache-control)" no-cache)" 2001)"
  done
  if [ -n "$asset" ]; then
    fetch "$base$asset" "$@"
    expect "$label: 해시 자산 $asset 는 immutable" "$(is "$STATUS$(has "$(header_value cache-control)" immutable)" 2001)"
  else
    fail "$label: index.html에서 해시 붙은 .js를 찾지 못했다"
  fi
  fetch "$base/assets/no-such-file.0123abcd.js" "$@"
  expect "$label: 없는 자산은 404" "$(is "$STATUS" 404)"
  expect "$label: 404 응답은 immutable이 아니다" "$(is "$(has "$(header_value cache-control)" immutable)" 0)"
  fetch "$base/some/spa/route" "$@"
  expect "$label: SPA 라우트는 index.html로 폴백(200, html)" "$(is "$STATUS$(has "$(header_value content-type)" text/html)" 2001)"
  fetch "$base/photos/x/pending/a.jpg" "$@"
  expect "$label: /photos/ 아래 그 외 경로는 404" "$(is "$STATUS" 404)"
}

check_site prod "$PROD"
fetch "$PROD/healthz"
expect "prod: /healthz 는 200" "$(is "$STATUS" 200)"

if [ -n "$HTTP_URL" ]; then
  fetch "$HTTP_URL/"
  expect "http→https 리다이렉트(3xx)" "$(has "301 302 307 308" "$STATUS")"
else
  skip "http→https 리다이렉트 (--http 없음)"
fi

if [ -n "$DEV" ] && [ -n "$DEV_KEY" ]; then
  for p in / /healthz /api/v1/version /config.json; do
    fetch "$DEV$p"
    expect "dev: 쿠키 없이 $p 는 404" "$(is "$STATUS" 404)"
  done
  fetch "$DEV/manifest.webmanifest"
  expect "dev: manifest는 쿠키 없이 200" "$(is "$STATUS" 200)"
  fetch "$DEV/?k=wrong-key"
  expect "dev: 틀린 키는 404" "$(is "$STATUS" 404)"
  fetch "$DEV/?k=$DEV_KEY"
  cookie="$(header_value set-cookie)"
  expect "dev: 올바른 키는 302로 / 이동" "$(is "$STATUS$(header_value location)" 302/)"
  expect "dev: 쿠키 속성(Secure, HttpOnly, SameSite=Lax, Max-Age=1209600)" \
    "$(is "$(has "$cookie" secure)$(has "$cookie" httponly)$(has "$cookie" samesite=lax)$(has "$cookie" max-age=1209600)" 1111)"
  expect "dev: 쿠키 이름은 fit_dev" "$(has "$cookie" "fit_dev=")"
  check_site dev "$DEV" -H "Cookie: fit_dev=$DEV_KEY"
  fetch "$DEV/healthz" -H "Cookie: fit_dev=$DEV_KEY"
  expect "dev: 쿠키가 있으면 /healthz 는 200" "$(is "$STATUS" 200)"
  fetch "$DEV/" -H "Cookie: fit_dev=wrong-key"
  expect "dev: 틀린 쿠키는 404" "$(is "$STATUS" 404)"
else
  skip "dev 게이트 (--dev, --dev-key 없음)"
fi

if [ "$FAILED" -gt 0 ]; then
  printf '\n%d개 점검 실패\n' "$FAILED"
  exit 1
fi
printf '\n엣지 정상\n'

````python
"""시험용 목 BE. 요청 본문을 끝까지 읽고 200을 돌려준다.

Caddy가 본문 한도를 넘는 요청을 413으로 거부하는지 보려면 upstream이 본문을 읽어야 한다.
읽지 않는 upstream은 본문이 한도를 넘기 전에 응답을 먼저 돌려줘서 한도가 드러나지 않는다.
"""
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer


class Handler(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"

    def do_POST(self):
        remaining = int(self.headers.get("Content-Length", 0))
        while remaining > 0:
            chunk = self.rfile.read(min(65536, remaining))
            if not chunk:
                break
            remaining -= len(chunk)
        body = b"ok"
        self.send_response(200)
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, fmt, *args):
        pass


ThreadingHTTPServer(("", 8080), Handler).serve_forever()
````

  docker run --rm -v "${EDGE_PROJECT}_state:/srv/fit/state" caddy:2.11.7 sh -c \

check_blue_green() {
  local before failures server_errors out
  before="$(active_color)"
  ok_if "전환: 처음 활성 색은 blue다" "$(is "$before" blue)"
  switch_prod_to green
  ok_if "전환: 상태 파일만 바꾸고 reload하기 전에는 그대로다" "$(is "$(active_color)" blue)"
  # reload하는 동안 요청이 계속 성공해야 한다. 호스트 경로(포트 포워더)와 compose 망 안쪽 경로를 함께 본다
  (for _ in $(seq 1 40); do http_code "$PROD/healthz"; sleep 0.1; done) > .tmp-edge-reload.log &
  local bg=$!
  # shellcheck disable=SC2016 # 변수는 컨테이너 안의 셸이 확장한다
  dc exec -T be-dev sh -c 'f=0; i=0; while [ $i -lt 150 ]; do i=$((i + 1)); wget -q -T 2 -O /dev/null http://caddy:9180/metrics || f=$((f + 1)); done; echo $f' > .tmp-edge-inner.log &
  local bg2=$!
  sleep 0.5
  out="$(reload || true)"
  wait "$bg" "$bg2" || true
  server_errors="$(grep -cE '^(4|5)[0-9][0-9]$' .tmp-edge-reload.log || true)"
  failures="$(tr -d '\r\n' < .tmp-edge-inner.log)"
  rm -f .tmp-edge-reload.log .tmp-edge-inner.log
  ok_if "전환: reload 후 활성 색은 green이다" "$(is "$(active_color)" green)"
  ok_if "전환: reload 중 호스트 경로에서 4xx·5xx 응답이 없다(발견 ${server_errors}건)" "$(is "$server_errors" 0)"
  ok_if "전환: reload 중 compose 망 안의 요청 150건이 모두 성공한다(실패 ${failures}건)" "$(is "$failures" 0)"
  # 문법이 틀린 상태 파일은 validate와 reload가 거부하고 현재 설정이 유지된다
  docker run --rm -v "${EDGE_PROJECT}_state:/srv/fit/state" caddy:2.11.7 sh -c "printf 'reverse_proxy be-prod-blue:8080 {\n' > /srv/fit/state/upstream-prod.caddy"
  if dc exec -T caddy caddy validate --config /etc/caddy/Caddyfile >/dev/null 2>&1; then fail "안전: 문법이 틀린 상태 파일을 validate가 통과시켰다"; else pass "안전: 문법이 틀린 상태 파일은 validate가 거부한다"; fi
  if reload >/dev/null; then fail "안전: 문법이 틀린 상태 파일을 reload가 받아들였다"; else pass "안전: 문법이 틀린 상태 파일은 reload가 거부한다"; fi
  switch_prod_to green
  reload >/dev/null
  ok_if "안전: reload가 거부된 뒤에도 서비스는 직전 설정(green)으로 계속 응답한다" "$(is "$(active_color)" green)"
  # 문법은 맞지만 없는 호스트를 가리키는 upstream은 validate와 reload를 통과한다. 그래서 reload 뒤 스모크가 필요하다
  docker run --rm -v "${EDGE_PROJECT}_state:/srv/fit/state" caddy:2.11.7 sh -c "printf 'reverse_proxy be-prod-nowhere:8080\n' > /srv/fit/state/upstream-prod.caddy"
  reload >/dev/null || true
  ok_if "스모크 필요: 없는 upstream은 reload를 통과하고 요청은 502다" "$(is "$(http_code "$PROD/healthz")" 502)"
  switch_prod_to blue
  reload >/dev/null
  ok_if "전환: blue로 되돌리면 활성 색이 blue다" "$(is "$(active_color)" blue)"
}

check_logs_and_surface() {
  local logs

}

#!/bin/sh
# 엣지 Caddy 설정의 형식(caddy fmt)과 문법(caddy validate)을 검사한다(설계 5절).
# caddy 이미지 안에서 저장소 루트를 작업 디렉터리로 돈다(CI의 lint:caddy, 로컬 러너).
# validate에는 환경변수와 상태 파일(upstream-*.caddy)이 필요해서 예제 env와 형식 견본을 쓴다.
# 인증서 단계(staging, production)와 HSTS(off, on)의 네 조합을 모두 확인한다.
set -eu

CONF=infra/edge/conf
bad=0

for f in "$CONF/Caddyfile" "$CONF"/acme/*.caddy "$CONF"/hsts/*.caddy infra/edge/state-sample/*.caddy infra/edge/test/mock/Caddyfile; do
  if ! caddy fmt --diff "$f" >/dev/null 2>&1; then
    echo "FAIL caddy fmt 필요: $f (caddy fmt --overwrite $f)"
    bad=1
  fi
done

mkdir -p /srv/fit/state
cp infra/edge/state-sample/*.caddy /srv/fit/state/
set -a
# shellcheck source=/dev/null
. infra/edge/edge.env.example
set +a
for mode in staging production; do
  for hsts in off on; do
    if ! ACME_MODE="$mode" HSTS_MODE="$hsts" caddy validate --config "$CONF/Caddyfile" --adapter caddyfile >/dev/null 2>&1; then
      echo "FAIL caddy validate: ACME_MODE=$mode HSTS_MODE=$hsts"
      bad=1
    fi
  done
done

if [ "$bad" = 0 ]; then
  echo "OK caddy (fmt, validate)"
fi
exit "$bad"
