# RB-04 디스크

- 검증 기준: develop `52c661d`, 2026-10-27. 서버 A·B에서 확인 명령을 실제로 실행했다. 정리 명령(이미지·볼륨 prune)은 실행하지 않았다(범위 참고).
- 쓰는 때: `FitDiskUsageHigh`(루트 80%), `FitDiskUsageCritical`(90%), `FitDiskFillingUp`(지금 추세면 24시간 안에 가득), `FitOpsDiskHigh`(B 80%)가 울릴 때. 배포 사전 점검이 `디스크 여유가 5GB 이상이다`에서 실패할 때.
- 준비: [README.md](README.md)의 접속.

## 1. 평상시 값

| 서버 | 루트 용량 | 사용(2026-10-27) | 큰 항목 |
|---|---|---|---|
| A | 309GB | 21GB(7%) | `/var/lib/containerd` 13GB(이미지와 빌드 캐시), `/var/lib/docker` 0.5GB(볼륨 0.35GB 포함) |
| B | 48GB | 13GB(26%) | Docker 이미지 3.3GB, 볼륨 3.8GB(대부분 CI 캐시), 금고 `/srv/vault/store` 0.4MB |

**Docker 29는 이미지를 `/var/lib/containerd`(containerd 스냅샷터)에 둔다.** `/var/lib/docker`만 `du`로 보면 이미지 용량이 빠진다.

## 2. 확인 명령

모두 읽기만 한다.

```bash
df -h /                                                       # 루트 사용률
sudo docker system df                                         # 이미지, 컨테이너, 볼륨, 빌드 캐시와 되찾을 수 있는 양
sudo du -xh --max-depth=1 /var/lib | sort -rh | head -n 6     # containerd, docker, apt 등
sudo du -xh --max-depth=1 /var /srv /home 2>/dev/null | sort -rh | head -n 10
sudo journalctl --disk-usage                                  # 시스템 로그(2026-10-27 A 40MB)
sudo du -sh /srv/fit/backups /srv/fit/predeploy /srv/fit/web  # A의 백업 사본, 사전 덤프, 정적 자산 풀
sudo du -sh /srv/vault/store /srv/vault/incoming              # B의 금고
```

`FitDiskFillingUp`은 추세 알림이라 지금은 여유가 있어도 울린다. `docker system df`가 되찾을 수 있다고 하는 양과 `du` 상위 항목으로 무엇이 늘고 있는지 먼저 가른다.

## 3. 늘어나는 것별 조치

컨테이너 로그는 컨테이너당 10MB × 3개로 제한돼 있다(`daemon.json`의 `json-file`). 로그 때문에 디스크가 차는 일은 드물다.

### A. 이미지와 빌드 캐시(서버 A)

배포마다 `be:<SHA>`, `fe:<SHA>` 이미지가 쌓인다. 주 1회(일요일, `fit-docker-prune.timer`) `be`·`fe`는 SHA 태그 최근 5개만 남기고, 쓰지 않는 이미지와 7일 넘은 빌드 캐시를 지운다. 롤백이 직전 색 이미지를 쓰므로 그 밖의 이미지는 지우지 않는다. 지금 한 번 돌리려면:

```bash
sudo bash /usr/local/lib/fit/docker-prune.sh      # 볼륨은 지우지 않는다. 사용 중인 이미지는 docker가 거부해 남는다("남김: ... (사용 중)")
sudo docker builder prune -f --filter until=24h   # 빌드 캐시를 더 공격적으로 지우고 싶을 때(A에서 빌드 캐시는 95개, 4.8GB였다)
```

### B. CI 캐시 볼륨(서버 B)

B의 볼륨 18개 중 13개는 쓰는 컨테이너가 없는 `runner-...-cache-...`다(2026-10-27, 3.7GB 되찾을 수 있음). GitLab 러너의 CI 캐시이므로 지워도 다음 잡이 다시 받을 뿐이고 그만큼 빌드가 느려진다. 디스크가 모자랄 때만 지운다.

```bash
sudo docker volume ls -qf dangling=true | wc -l            # 쓰는 컨테이너가 없는 볼륨 수
sudo docker volume prune -a -f                              # 쓰는 컨테이너가 없는 볼륨만 지운다(실행 중인 감시 스택의 볼륨은 남는다)
```

`-a`가 있어야 이름 있는 볼륨(러너 캐시가 여기에 든다)까지 지운다. `-a` 없이는 이름 없는 볼륨만 지워서 캐시가 남는다(Docker 29.9.2의 `docker volume prune --help`로 확인). B의 `docker-prune.sh`는 7일 넘게 쓰지 않은 이미지만 지우고 볼륨은 지우지 않는다. `fit-ops-*` 컨테이너(Prometheus-B 데이터 포함)가 떠 있는 동안에만 `volume prune`을 쓴다. **`docker compose down -v`나 `docker volume rm`을 A·B의 데이터 볼륨에 쓰지 않는다.**

### C. 데이터(서버 A)

지우면 안 되는 볼륨: `fit-data_*`(Postgres, OpenSearch, Redis, Garage), `fit-edge_caddy_data`(인증서, 재발급 한도), `fit-obs_*`(Prometheus 5GB 상한, Grafana). 크기는 `sudo docker system df -v`의 볼륨 목록으로 본다. 어느 하나가 커졌으면 그 서비스의 런북이나 팀(BE·AI)과 상의한다.

- 사전 덤프(`/srv/fit/predeploy`)는 환경별 최근 5개만 남는다. 배포 중 마이그레이션이 있을 때 만든다.
- 백업 사본(`/srv/fit/backups`)은 4시간 단위 48시간과 하루 1벌 14일 규칙으로 줄어든다(`infra/backup/README.md`). 이 규칙이 안 돌면 RB-06이다.
- 정적 자산 풀(`/srv/fit/web/<환경>/pool`)은 14일 동안 어느 릴리스에도 없던 파일을 배포가 지운다.

### D. 금고(서버 B)

`/srv/vault/store`는 `vault-ingest.sh`가 10분마다 보관 규칙을 적용한다. 격리 폴더(`store/quarantine`)가 커지면 RB-06이다.

### E. 시스템 로그

`sudo journalctl --vacuum-size=200M`으로 줄인다(기본 한도는 파일시스템의 10%라 보통 필요 없다. 지금은 40MB).

## 4. 되돌리기

- `docker image rm`/`prune`으로 지운 이미지는 되돌릴 수 없다. 롤백에 필요한 직전 SHA(`PREVIOUS_SHA`) 이미지가 남았는지 지우기 전에 확인한다: `sudo grep -E '^(DEPLOYED_SHA|PREVIOUS_SHA)=' /srv/fit/state/deploy-<환경>.env`.
- 지운 이미지가 필요해지면 CI의 `build:images`를 다시 돌려 만든다(B가 살아 있어야 한다. RB-02b는 이미지가 서버에 있을 때만 쓴다).
- 빌드 캐시와 러너 캐시 볼륨은 지워도 다음 빌드가 다시 만든다.

## 이 런북을 따라 해 본 범위

- 직접 실행함(2026-10-27, A·B): `df`, `docker system df`, `du` 분포(A의 이미지가 `/var/lib/containerd`에 있다는 사실 포함), `journalctl --disk-usage`, `docker volume ls -qf dangling=true`, `docker-prune.sh`와 타이머 존재, `docker info`의 스냅샷터 확인.
- 실행하지 못함: `docker-prune.sh`, `builder prune`, `volume prune`, `journalctl --vacuum-size`(운영 서버의 이미지·볼륨을 지우는 명령이라 실제로 돌리지 않았다). 디스크가 80%에 가까운 상황에서의 조치는 만나 보지 못했다(A는 7%, B는 26%).
