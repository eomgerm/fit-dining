# GMS 프롬프트 평가

직접 입력 해석(`direct_input.py`)과 장소 페르소나(`persona.py`)의 프롬프트를 GEPA로 최적화하고 평가하는 스크립트다. 평가셋은 `data/`의 합성 데이터다. 실행법은 `ai/README.md` "프롬프트 최적화"에 있다. 두 스크립트는 제품 코드의 모델 설정(`MODEL`, `REASONING_EFFORT`)을 그대로 쓴다.

## 결과 (2026-11-06, `gpt-4o-mini`에서 `gpt-6-luna`로)

직접 입력 해석, 리뷰 추출, 장소 페르소나가 쓰던 공유 기본 모델 `gpt-4o-mini`(temperature 0)를 `gpt-6-luna` 추론 `none`으로 바꿨다. 요청 해석(`experiments/interpretation`)은 2026-11-05에 먼저 바꿨다. `gpt-6-luna`는 temperature 0을 받지 않아 temperature는 보내지 않는다. 측정 스크립트는 저장소 밖에서 돌렸고(동시 4개), 채점과 입력 구성은 이 폴더의 코드를 그대로 썼다. 공유 기본값 `fit_ai.gms.MODEL`은 그대로다.

### 직접 입력 해석 (`fit_ai.taste.direct_input`)

`data/direct_input.jsonl`의 test 108개를 3번씩 돌렸다. 점수는 `direct_input.py`의 `match`와 같은 (kind, code, like) 자카드다. 프롬프트와 strict 스키마는 그대로다.

| | 평균 점수(3번) | 완전 일치 /108 | p50 | p95 | 최대 | 3초 초과 | 실패 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `gpt-4o-mini` | 0.852 / 0.838 / 0.869 | 89 / 87 / 90 | 1.36초 | 2.34초 | 6.63초 | 5/324 | 0 |
| 지금: `gpt-6-luna` 추론 `none` | 0.932 / 0.935 / 0.921 | 99 / 100 / 98 | 1.43초 | 1.87초 | 5.82초 | 1/324 | 0 |
| `gpt-6-luna` 추론 `low` | 0.931 / 0.926 / 0.958 | 99 / 99 / 103 | 1.71초 | 3.58초 | 9.53초 | 35/324 | 0 |
| `gpt-6-luna` 추론 `medium` | 0.949 / 0.951 / 0.946 | 102 / 101 / 100 | 1.93초 | 4.38초 | 6.14초 | 68/324 | 0 |

`none`이 나아진 문장 16개는 주로 부정·불만 문장이다. `gpt-4o-mini`는 "싫다"를 코드 없는 비선호 (taste, null, false)로 흘렸는데(324번 중 19번) `none`은 4번이었다. 나빠진 문장은 3개다. `low`는 `none`과 점수 범위가 겹치고 느린 응답만 늘었다. `medium`은 0.02쯤 높지만 응답의 21%가 3초를 넘는다. 입력을 멈추면 바로 칩을 띄우는 화면이고, 운영 대기 시간 5초에 재시도가 한 번 있어 `none`을 골랐다.

참고로 OpenRouter의 Jev(`typesafe/jev-1.14`, 코드마다 want/avoid/none을 고르는 방식)도 쟀다. 가장 나은 조합이 평균 0.672, p95 0.48초였고, 글을 쓰지 못해 문장 칩과 근거 구절을 만들 수 없어 쓰지 않았다.

### 리뷰 추출 (`fit_ai.place.extract`)

정답이 있는 평가셋이 없다. 수집본(`~/fit-ai-data/raw`)에서 곱창·중식당·카페·바·요리주점 5곳을 골라, 장소마다 똑같은 리뷰를 합친 뒤 20자 이상 리뷰 앞 10개씩(50개, 묶음 5개)을 모델마다 한 번 돌렸다. 제품 `extract()`를 그대로 불렀다. 리뷰 원문과 리뷰별 결과는 저장소 밖에 두었다.

| | 항목 | 코드 항목 | 검사에서 버려진 항목 | 실패한 리뷰 | 묶음당 시간(5개) | 중앙값 |
| --- | --- | --- | --- | --- | --- | --- |
| `gpt-4o-mini` | 63 | 28 | 36 | 0 | 9.3, 18.4, 11.6, 17.5, 12.6초 | 12.6초 |
| 지금: `gpt-6-luna` 추론 `none` | 108 | 44 | 1 | 0 | 4.5, 8.1, 12.6, 9.2, 8.1초 | 8.1초 |

(코드, 방향) 집합이 같은 리뷰는 50개 중 21개다. 다른 29개는 이번 작업에서 Claude Code가 리뷰 원문과 대조해 판정했다(사람 판정도, 블라인드도 아니다). 리뷰별 비교표는 저장소 밖에 있다.

- `gpt-6-luna`가 나음, 약 21개: 조용하다는 말을 QUIET(4개), 인테리어가 예쁘다는 말을 PRETTY_SPACE(3개)로 잡았고, 뷰·혼술·공연(GOOD_MUSIC)도 잡았다. `gpt-4o-mini`는 리뷰에 없는 FAST_SERVING, 음악과 관계없는 대관 이야기에 GOOD_MUSIC, 붐빈다는 말에 LIVELY -1(프롬프트가 금지한 해석)을 붙였다.
- `gpt-4o-mini`가 나음, 2개: 1인 매장이라는 말의 PURPOSE_SOLO, 친구 여럿과 왔다는 말의 PURPOSE_GROUP을 `gpt-6-luna`가 놓쳤다.
- 둘 다 애매함, 약 6개: `gpt-6-luna`도 여유롭다는 말에 PURPOSE_TALK, 분위기가 좋다는 말에 COZY를 붙였다.

`gpt-6-luna`는 코드 없는 문장 항목, 특히 누구와 어떤 일로 왔는지 같은 방문 맥락도 더 많이 남긴다(18개, `gpt-4o-mini`는 0개). 정확도가 낫고 더 빨라 바꿨다. 표본이 50개, 1번이라 코드별 차이는 크기만 참고한다. 기존 장소 프로필은 `gpt-4o-mini`로 뽑은 그대로다. `build_place_profiles.py`는 저장된 본문 추출(`analysis.jsonl`)과 페르소나(`personas.jsonl`)를 다시 쓰므로, 새 모델로 다시 뽑으려면 그 파일을 지우고 돌려야 한다.

### 장소 페르소나 (`fit_ai.place.persona`)

`data/persona.jsonl`의 test 100곳 중 slice마다 앞 2곳(20곳)을 한 번씩 돌렸다. 채점은 `persona.py`의 `rules`(코드)와 `search`(임베딩)다. "데이터 설명 말"은 리뷰 번호(r1 등), 건수, 키워드·투표, 근거, 확인됐다·언급됐다·표시됐다, 페르소나·묶었다 같은 말이 든 페르소나 수다("리뷰"라는 낱말만 쓴 것은 세지 않았다).

| | rules | search | 감점 없는 장소 | 장소당 페르소나 | 데이터 설명 말 | 생성 p50 / 최대 |
| --- | --- | --- | --- | --- | --- | --- |
| `gpt-4o-mini` | 0.967 | 0.817 | 14/20 | 3.5 | 12/71 | 11.0 / 17.7초 |
| `gpt-6-luna` 추론 `none`, 전 프롬프트 | 0.997 | 0.887 | 19/20 | 4.7 | 72/93(리뷰 번호 31) | 9.5 / 12.2초 |
| `gpt-6-luna` 추론 `none`, 판단 과정 금지 지시(평가 장소에서 따온 예시) | 0.994 | 0.879 | 18/20 | 4.0 | 0/81 | 9.0 / 12.4초 |
| 지금: `gpt-6-luna` 추론 `none`, 판단 과정 금지 지시(평가셋에 없는 예시) | 0.980 | 0.884 | 15/20 | 4.2 | 0/84 | 8.0 / 11.1초 |

`gpt-6-luna`는 전 프롬프트에서 "r8은 차슈덮밥의 불맛을 좋게 평가했다", "단체 모임 키워드 투표가 14건으로 가장 많다", "점심 코스를 중시하는 페르소나로 구분했다"처럼 입력을 보고 판단한 과정을 썼다. reason은 추천 이유로 화면에 나가는데 `rules`·`search`는 이를 감점하지 않는다. 그래서 프롬프트에 세 필드가 화면에 나간다는 점과 쓰지 말 말, 바꿔 쓴 예 두 개를 더했다. 처음 넣은 예는 위 출력에서 따온 문장이라 재측정 20곳 중 2곳의 메뉴(차슈덮밥)가 들어 있었고, 그 장소 출력이 예를 거의 그대로 옮겼다. 예시 메뉴가 다른 장소의 페르소나에 지어낸 평가로 끼어들 수도 있어, 평가셋에 없는 메뉴(감자옹심이)와 흔한 키워드(가성비)로 바꿔 다시 쟀다. 두 번 모두 그런 말은 없어졌고 예 문구를 옮긴 출력도 없었다. 지금 프롬프트의 감점 5곳은 아쉬웠어요 특징을 다룬 페르소나 빠짐 2곳(3건), 방향 1곳, name이 5단어인 형식 2곳이다. 전 프롬프트(19/20)보다 많지만 한 번만 돌린 20곳이라 흔들림과 구분하지 못한다.

slice별 search(`gpt-4o-mini` → 지금): keyword_heavy 0.72 → 0.93, app_mix 0.85 → 0.95, conflict 0.83 → 0.92, sparse 0.86 → 0.94, neg_minority 0.83 → 0.92, summary_trap 0.85 → 0.90, generic 0.84 → 0.86, menu_heavy 0.78 → 0.84, simple 0.88 → 0.84, multi 0.74 → 0.73. 장소가 slice마다 2곳이라 slice 하나의 차이는 흔들림 안이다.

문체도 달라졌다. `gpt-4o-mini`는 "~합니다"체에 흐린 문장이 많고, `gpt-6-luna`는 "~이다"체에 메뉴와 맛을 구체적으로 쓴다. 이전에 judge 최적화가 사람 비교와 반대로 나온 적이 있어(`persona.py` 머리말), 채택은 사람 블라인드 비교(slice마다 1곳, 10곳, `gpt-4o-mini`와 지금 프롬프트 출력을 A/B로 섞음)로 정한다. 문체 차이로 모델이 드러날 수 있다. 코드는 `gpt-6-luna`로 바꿔 두었고, 사람 비교에서 지면 되돌린다. 비교 결과는 아직 없다.
