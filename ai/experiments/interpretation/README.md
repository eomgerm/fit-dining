# 요청 해석 평가

요청 해석(`src/fit_ai/match/interpretation.py`)이 질의를 얼마나 맞게 조건으로 바꾸는지 잰다. 실제 GMS를 부른다.

```bash
cd ai
uv run --env-file .env python experiments/interpretation/run.py --runs 3 --label <이름>
```

- `cases.json`: 질의 54개와 기대 답. `codes`는 반드시 나와야 할 코드, `optional`은 나와도 틀리지 않은 코드, `uncovered`는 코드표로 못 잡아 벡터용 문장에만 남아야 할 표현이다. 기대 답은 41이 정한 초안이라 팀 확인이 필요하다.
- `results/<이름>.json`: 질의별 결과. 같은 질의를 `--runs`번 돌려 답이 흔들리는지도 본다.

프롬프트 예시는 이 질의들과 겹치지 않는 문장으로 고른다. 이 질의로만 프롬프트를 고치면 여기에만 맞춰질 수 있으니, 새 질의를 받으면 따로 모아 확인한다.

## 결과 (2026-10-27)

| | v1 (고치기 전) | v4 (고친 뒤) |
| --- | --- | --- |
| LLM 해석 전부 맞음 | 87/100 (87%) | 158/162 (98%) |
| 코드 정밀도 / 재현율 | 100% / 92% | 98% / 99% |
| 업종 / 근처 | 89% / 100% | 99% / 100% |
| LLM 실패로 규칙에 떨어짐 | 0 | 0 |
| 실행마다 답이 달라진 질의 | 2/50 | 2/54 |
| 규칙 해석 전부 맞음 | 35/50 (70%) | 47/54 (87%) |
| 평균 시간 | 1.33초 | 1.38초 |

v1은 질의 50개를 2번, v4는 재현 질의 4개를 더한 54개를 3번 돌렸다. 마지막 결과 v6(54개를 2번)은 LLM 해석 전부 맞음 106/108(98%), 규칙 해석 47/54(87%)다. 결과 파일은 v6(`results/2026-10-27-v6.json`)만 남기고 이전 결과는 위 표의 숫자로만 남긴다.

고친 것:

- 프롬프트: 음식·메뉴는 식당, 술 마시는 곳은 술집으로 본다. 메뉴는 음식 종류 코드로 바꾼다. 부정한 조건도 빠뜨리지 않는다. 요청에 없는 코드(식당만 보고 `FOOD_KOREAN`, 모임만 보고 `GROUP`)는 넣지 않는다. 예시 5개를 넣었다.
- 코드: `nearby`가 null이면 false로 본다(전에는 해석 전체를 버렸다). 역이 있으면 근처 검색이 아니다.
- 규칙 해석: 음식 낱말은 식당, "A 말고"의 A는 업종·역으로 고르지 않는다, "수다", "단체석"을 더했다.

남은 것:

- "매운 거 말고 담백한 국물 요리"에 엉뚱한 코드(`PURPOSE_TALK`)가 붙고 업종이 빠질 때가 있다.
- "역삼역 초밥집"에서 `FOOD_JAPANESE`가 가끔 빠진다.
- 코드표로 못 잡는 표현(와인, 디저트, 늦게까지, 반려견, 콘센트, 국물)은 7개 모두 벡터용 문장에 남았다. 벡터 검색과 정렬 LLM에는 들어가지만 근거 판정·등급·카드에는 빠진다.
