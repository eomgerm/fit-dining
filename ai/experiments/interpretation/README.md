# 요청 해석 평가

요청 해석(`src/fit_ai/match/interpretation/`)이 질의를 얼마나 맞게 조건으로 바꾸는지 잰다. 실제 GMS를 부른다.

```bash
cd ai
uv run --env-file .env python experiments/interpretation/run.py --runs 3 --label <이름> [--model gpt-6-luna] [--effort none]
```

- `cases.json`: 질의 54개와 기대 답. `codes`는 반드시 나와야 할 코드, `optional`은 나와도 틀리지 않은 코드, `uncovered`는 코드표로 못 잡아 벡터용 문장에만 남아야 할 표현이다. 기대 답은 41이 정한 초안이라 팀 확인이 필요하다.
- `results/<이름>.json`: 질의별 결과. 같은 질의를 `--runs`번 돌려 답이 흔들리는지도 본다.
- `--model`, `--effort`는 해석 모델과 추론 강도를 바꾼다. 없으면 해석 코드의 값(`interpretation.MODEL`, `REASONING_EFFORT`)이다. 해석은 temperature를 보내지 않는다(`gpt-6-luna`는 0을 받지 않는다).

프롬프트 예시는 이 질의들과 겹치지 않는 문장으로 고른다. 이 질의로만 프롬프트를 고치면 여기에만 맞춰질 수 있으니, 새 질의를 받으면 따로 모아 확인한다.

## 결과 (2026-11-05, 해석 모델 `gpt-6-luna`와 코드 확인 삭제)

코드 확인(`_checked`)의 규칙 20개를 하나씩 꺼 보며 쟀다. 질의는 이 폴더의 80개와 따로 만든 새 질의 21개(지역 표현, 오타, 후속, 부정이 섞인 질의. 저장소에는 넣지 않았다)다. 측정 스크립트는 이 폴더의 `run.py`가 아니라 세션 임시 폴더에서 돌렸고, 채점은 `run.py`의 `_check`를 그대로 썼다.

| --- | --- | --- | --- | --- |
| `gpt-4o-mini` + 코드 확인(전), 2번씩 | 156/160 | 32/42 | 1.55초 | 0 |
| `gpt-4o-mini`, 코드 확인 없음(전 프롬프트), 2번씩 | 132/160 | 27/42 | | |
| `gpt-6-luna` 기본 추론, 코드 확인 없음(전 프롬프트), 2번씩 | 158/160 | 40/42 | 2.77초 | 4/202 |
| 지금: `gpt-6-luna` 추론 `none`, 새 프롬프트, 코드 확인 없음, 4번씩 | 317/320 | 84/84 | 1.71초 | 0/404 |

`gpt-4o-mini`에서는 규칙이 32건을 맞게, 3건을 틀리게 고쳤다. 고친 실수는 "○○역 근처"를 근처 검색으로 냄, 요청에 없는 근처를 지어 냄, 싼 곳을 가성비로 냄, 메뉴·시설을 놓침, 부정이 걸리는 범위를 잘못 읽음이었다. `gpt-6-luna`에서는 이 실수가 나오지 않아 규칙이 4건만 맞게(검색에 쓰지 않는 넓은 말 메뉴 "고기") 고쳤고, 시간 규칙이 "자정까지"를 지워 2건을 틀리게 했다. 그래서 코드 확인을 빼고 규칙이 하던 일을 프롬프트로 옮겼다. 프롬프트는 측정에서 드러난 실패를 보고 세 번 고쳤다. 마지막 두 판의 차이는 질의마다 4번 중 1~2번이 오락가락하는 정도라(temperature 기본값 1) 더 고치지 않았다.

흔들림(같은 질의 4번 사이에 거르기·점수 값이 달라짐)은 지금 설정에서 101개 중 7개다. "역삼역 회식 장소", "주변에 혼밥할 만한 곳"은 업종이 가끔 비고, "빨리 먹고 나올 수 있는"의 코드를 4번 중 2번, 아시아 음식 코드와 쌀국수 메뉴를 4번 중 1번 놓쳤다. 응답 시간은 동시 6개로 쟀고 부하는 걸지 않았다.

## 결과 (2026-11-04, 이번 요청만 분류별로)

LLM이 이전 조건과 합친 조건 대신 이번 요청의 분류별 조각(업종·음식 종류·맛은 `{code, want}`, 특징은 코드표 코드가 붙은 조각, 시설은 코드 목록, 인원은 숫자)을 내고, 이전 조건과는 코드가 합친다(`docs/comparison/conditions-v3.md`). 칸마다 고를 코드만 보여 준다. 같은 질의 80개를 `gpt-4o-mini`로 두 번씩 돌렸다. 기준은 `results/2026-11-03-menu-split-guard.json`이다.

| --- | --- | --- | --- |
| 2026-11-03 (기준) | 149/160 | 1.69초 | 67/80 |
| 이번 요청만 분류별로 | 156/160 | 1.86초 | 68/80 |

맞게 된 질의는 B6 "인테리어 예쁜 카페", B9 "뷰 좋은 루프탑 바", D1 "주차되는 식당", I8 "점심에 빨리 먹고 나올 수 있는 곳"(모두 코드 0/2 → 2/2), L3 "회사 근처 점심"(업종)이다. 시설 칸을 따로 두고 놓친 시설은 규칙이 채운다. 틀리게 된 질의는 T2 "지금 열려 있는 카페"(2/2 → 0/2)로 요청에 없는 "근처"를 지어 냈다. 요청에 없는 근처 말로 낸 근처는 버리게 고치고 두 번 다시 재서 맞았다. L2 "코엑스 근처 일식"은 코엑스를 빠뜨린다(1/2 → 0/2, 전부터 남은 문제). 결과 파일은 `results/2026-11-04-turn.json`이다(T2를 고치기 전 결과).

## 결과 (2026-11-03, 메뉴와 음식 종류 나눔)

메뉴에 음식 종류 코드를 붙이지 않고(초밥 → 일식 안 함), 음식 종류는 "일식", "중국집"처럼 말했을 때만 코드로 둔다. 빼 달라는 음식은 `avoid_foods`다. 그래서 메뉴만 말한 질의 5개(E2 초밥집, E4·P1 파스타, E5 쌀국수, S2 스시)의 기대 답에서 음식 종류 코드를 빼고 메뉴 조각을 넣었고, R4의 허용 코드도 뺐다. 피하는 음식 채점은 `avoid_menus`에서 `avoid_foods`로 바꿨다. `gpt-4o-mini`로 두 번씩 돌렸다.

| | 전체 | 평균 시간 |
| --- | --- | --- |
| 프롬프트만 바꿈 | 141/160 | 1.75초 |
| 음식 종류 낱말이 없으면 LLM의 음식 종류 코드를 떼는 코드 확인 추가 | 149/160 | 1.7초 |

프롬프트만 바꾸면 `gpt-4o-mini`가 여전히 "초밥집", "스시"에 일식, "쌀국수"에 아시아 음식을 붙였다(6번). 코드 확인으로 막았다. 대신 "인테리어 예쁜 카페", "주차되는 식당"의 코드를 빠뜨리는 일이 생겼다(전에는 맞혔다). 음식 코드 규칙을 코드 칸 설명에 합친 짧은 프롬프트도 148/160이라 차이가 없어 나눈 쪽을 남겼다. 결과 파일은 `results/2026-11-03-menu-split-guard.json`이다.

## 결과 (2026-11-02, 분류별 조각)

요청을 분류별 조각(지역, 메뉴·음식, 시간, 가격, 가게 이름, 특징)으로 나누고 질의를 80개로 늘렸다. 새 질의는 지역 5, 시간 4, 가격 4, 가게 이름 3, 오타·줄임말 4, 피함 3, 지역 여러 개·거리 3개다. 분류를 정하면서 기대 답이 바뀐 1차 질의가 7개다("비싼 데 말고"는 가성비가 아니라 가격, "와인"·"디저트"는 메뉴, "늦게까지"는 시간, "반려견"·"콘센트"는 특징). 모두 두 번씩 돌렸다.

| | 1차와 기대 답이 같은 47개 | 기대 답이 바뀐 7개 | 새 질의 26개 | 전체 | 평균 시간 |
| --- | --- | --- | --- | --- | --- |
| 1차 프롬프트(v6) | 94/94 | | | | 1.6초 |
| 분류만 더한 프롬프트, `gpt-4o-mini` | 77/94 | 6/14 | 34/46(23개) | 117/154 | 1.55초 |
| 코드 확인 추가, `gpt-4o-mini` | 90/94 | 14/14 | 44/52 | 148/160 | 1.7초 |
| 코드 확인 추가, `gpt-4.1` | 94/94 | 14/14 | 52/52 | 160/160 | 1.3초 |

분류만 더했을 때 1차 질의가 나빠진 까닭과 고친 것:

- 후속(12번 중 2번): 이전 조건은 1차 꼴(`station`)인데 출력 꼴은 지역 목록이라 LLM이 이전 역을 잇지 못했다. 이전 조건을 출력 꼴로 바꿔 보여 주니 4개 질의가 0/2에서 2/2가 됐다.
- 근처(6번 중 2번): 반드시 채우던 `nearby`가 비워도 되는 지역 칸이 되자 LLM이 비웠다. 규칙이 근처 말을 찾으면 근처로 둔다.
- 음식·부정: 새로 둔 "피하는 코드" 칸을 "웨이팅 긴 데는 싫어", "매운 거 먹고 싶다"에도 써서 뜻이 뒤집혔다. 칸을 없애고 피함은 메뉴와 업종에만 두며, 요청에 피하는 말이 없으면 원함으로 되돌린다.
- 프롬프트가 2,654자에서 4,963자로, 출력 칸이 7개에서 13개로 늘었다. 같은 프롬프트에서 헷갈린 질의 9개를 `gpt-4.1`은 18번 중 16번 맞혔다(`gpt-4o-mini`는 3번).

`gpt-4o-mini`에 남은 것은 규칙으로 못 막는 이해 문제다. "코엑스 근처 일식"에서 코엑스를 빠뜨리고, "빨리 먹고 나올 수 있는"을 짧은 대기로 보고, "뷰 좋은 루프탑 바"에서 전망을 빠뜨리고, "만원 이하"에 가성비를 붙이고, 고깃집을 한식으로 본다. `gpt-5`, `gpt-6` 계열은 공유 모듈이 보내는 `temperature: 0`을 받지 않아(400) 재지 못했다. 결과 파일은 `results/2026-11-02-checked-4o-mini.json`, `results/2026-11-02-checked-4.1.json`이고, 분류만 더한 결과는 `results/2026-11-02-segments.json`이다.

v1은 질의 50개를 2번, v4는 재현 질의 4개를 더한 54개를 3번 돌렸다. 마지막 결과 v6(54개를 2번)은 LLM 해석 전부 맞음 106/108(98%), 규칙 해석 47/54(87%)다. 결과 파일은 v6(`results/2026-10-27-v6.json`)만 남기고 이전 결과는 위 표의 숫자로만 남긴다.

고친 것:

- 프롬프트: 음식·메뉴는 식당, 술 마시는 곳은 술집으로 본다. 메뉴는 음식 종류 코드로 바꾼다. 부정한 조건도 빠뜨리지 않는다. 요청에 없는 코드(식당만 보고 `FOOD_KOREAN`, 모임만 보고 `GROUP`)는 넣지 않는다. 예시 5개를 넣었다.
- 코드: `nearby`가 null이면 false로 본다(전에는 해석 전체를 버렸다). 역이 있으면 근처 검색이 아니다.
- 규칙 해석: 음식 낱말은 식당, "A 말고"의 A는 업종·역으로 고르지 않는다, "수다", "단체석"을 더했다.

남은 것:

- "매운 거 말고 담백한 국물 요리"에 엉뚱한 코드(`PURPOSE_TALK`)가 붙고 업종이 빠질 때가 있다.
- "역삼역 초밥집"에서 `FOOD_JAPANESE`가 가끔 빠진다.
- 코드표로 못 잡는 표현(와인, 디저트, 늦게까지, 반려견, 콘센트, 국물)은 7개 모두 벡터용 문장에 남았다. 벡터 검색과 정렬 LLM에는 들어가지만 근거 판정·등급·카드에는 빠진다.
